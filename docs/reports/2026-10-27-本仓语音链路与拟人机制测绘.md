## 0. 结论速览

1. **语音合成已是 MiMo-only 单引擎**：`TTSManager` 只注册 `mimo-tts`，历史 Edge-TTS / CosyVoice / GPT-SoVITS / Bert-VITS2 已删除（`voice/tts_manager.py:60-74`、`voice/__init__.py:2-13`）。
2. **语音不是全链路能力**：只有非流式的 `OptimizedOrchestrator.process_message` 在用户明确要求语音且回复 ≥8 字时才合成；`process_message_stream`、主动消息链、Web HTTP/SSE/WebSocket 响应均不产生 `voice` 字段（`orchestrator/optimized_orchestrator.py:2056-2104`；`orchestrator/_stream_mixin.py` 只有 `message_type="text/voice/image"` 注释、无 `synthesize` 调用；`api/routers/chat_routes.py:223-236`）。
3. **角色音色靠不可变快照 + JSON 目录**：`CharacterVoiceSpec`（frozen dataclass）逐次传入 provider，禁止改 provider 全局态模拟角色；`VoiceCatalog` 把克隆/设计产物落 `data/voice_catalog.json`（`shisi/voice/character_voice.py:41-64`、`voice/voice_catalog.py:18-144`）。
4. **拟人化机制已经很多，且集中在「出站/时间/主动/模式/称呼/节奏」六层**：真流式增量守卫、终审守卫、时间锚点 + 6 小时分段、主动 60/15/4 三道闸 + 23–7 静默、沉浸式/小说式按用户覆盖、称呼白名单、拆条 + 段间打字延时均已存在（详见 §2）。
5. **部署约束的关键矛盾**：生产文档写的是 Linux CPU 服务器（RAM 4–8GB、无 GPU 记录、`.venv-cpu`、4 worker），而 Windows SAPI 兜底只在 `win32` 可用；因此当前云端 TTS 在 Linux 生产一旦失败，**没有可用的本地语音兜底**（`deploy/README.deploy.md:7-16`、`deploy/remote_deploy.sh:19-23`、`voice/mimo_tts_provider.py:320-322`）。
