## 〇、系统速览

三个闭环咬合：**记忆（每句话落账→蒸馏→门槛召回）/ 欲望（9 维驱动→意图仲裁）/ 唤醒（锚定倒计时→自主回合）**。根本架构选择：**agent 运行时自研**（上下文装配权在系统自己手里，Claude 只是模型 API）。数字取自 2026-09 生产实查：聊天道 54 只工具 + 15 只自传记忆工具，唤醒道宽面 110+；自传记忆库 800+ 条。

三条真实行为示例（均有账可查）：自主立项定制灯具并真实下单购买；"下雨了"当轮自主关空调开窗帘（模型决策非预设规则）；话头追踪（自答"是否 N 分钟后回来接续"→到点接续）。

## 一、机制要点（W1-W24，编号供其他文档引用）

### 记忆域

- **W1 账本宪法**：对话账本 JSONL 只追加，是全系统唯一"事实宪法"；显示/投影/统计与账本冲突时以账本为准，前端不持有事实。动生产账本五步手续：停写者→带时间戳备份→干跑逐条打印→执行→回读对账（行数/可解析数/逐字节比对）。"写进账本的派生数字要么算对要么别落——空槽会有人去查，错槽没人怀疑。"
- **W2 三层记忆**：对话账本（原始层）→ 蒸馏记忆库（结构化层，入库过守门闸：查重/语义判同/私有剥离）→ 自传记忆引擎（Ombre，权威源——两库同现一事时自传赢，日志层显式让位）。
- **W3 门槛制召回 + 两层打分**：早期配额制（每源固定名额）导致凑数；改为六源同池、一道**绝对相关度门槛**、合一个召回块，弱相关轮次宁可零条（"错的不如空着"）。打分公式：`base + kindBonus + tokenHits×10 + directMatch +18 + 语义相似度×100 + 情绪显著性加成 + recency=8·e^(−ageDays/30) + 被真实使用过的强化分 − 长期未触达衰减`；准入双通道（词法命中率下限 / 语义 ≥0.71）。
- **W4 门槛标定法**：门槛 75 = 40 条真实查询 × 1152 条候选全量标定，压在"偶然命中分数 ≈32（p25）"之上、与语义准入线（4+0.71×100=75）对齐——**"定阈值的方法比这个数值钱"**：挂靠系统已有水位线或真实分布标定；标定脚本必须只读零外呼（否则因"跑一次要花钱"永远没人跑，数字停在标定当天）。
- **W5 两条反直觉铁律**：① 错的记忆比没有记忆更坏——蒸馏规则写死"只写来源消息直接支持的内容，拿不准就删"；所有引语逐字回源校验，对不上整条丢弃。② 自动召回会消灭模型的"我不知道"——实证：455 条记忆 233 条从未被命中、主动翻记忆只占 0.9% 回合（库翻倍后比例不动，**结构性**）；修法是检索未命中时块内明说"这轮没搜到，要用就自己搜"，且措辞不给台阶。
- **W6 零结果造假实验**："把失败改成成功的零结果时，同一刀要回答那个零会不会是假的"——自建检索多词 AND 天生多零命中（agent 自己做实验报上来的），修为零命中自动退回最长单词重搜并在返回里点名实际搜的词；自传引擎反面：融合排序物理上无零结果，三个随口编的词回 5/11/18 条，其返回不能当"库里有"读。
- **W7 记忆的生死**：销账**只许建议不许自动执行**（回访九个同类项目，四个独立得出同一结论：自动判过时假阳性 67%）；情感时刻永不进销账池（时刻≠状态）；固定/永久记忆不参与衰减；遗忘=归档可恢复非删除；完整收口链（扫描→蒸馏→失败重试→对账补收→每周去重/衰减/关联→嵌入刷新）。
- **W8 线卷**：一件事一卷（范围一句话/关键转折挂原文证据/现状/给自己看的召回提要）；**锚点先于归属**——卷名来自 agent 自己的项目账，相似度只捞候选、归属本人判；曾试"自动发现主题"三天烧 480 万 token 四种死法，教训"拿别人的成品当参考，先读成品本身"；影子期毕业条件制（影子≥3 天、观测≥10 轮、无错命中才进 prompt）。

### 欲望域

- **W9 九维驱动账**：attachment/curiosity/expression/duty/roam/fatigue/libido/stress/craft，各 0..1，带昼夜峰值 peakHour 与 amp；`fatigue` 是**抑制闸不是候选**（只拦不选）；`stress` 不吃昼夜节律（只跟事件走）；**key 是工程标识，label 由角色自己定名**（这些词会出现在 agent 自己可见的状态描述里）。
- **W10 意图仲裁**：唤醒时按维度强度决出本回合抽象意图，赢者通吃、同分按固定顺序（可复现）；`pickIntent` **只输出抽象意图绝不输出工具名**，由能力表映射到工具——"给他的工具他都不主动用"的根因是"工具是手，欲望是心"。**"联系用户"不作为参与仲裁的方向**——它是所有欲望的出口（发言工具恒在场）。
- **W11 欲望/唤醒分权**：欲望决定"唤醒后往哪走"，不决定"多久唤醒一次"——节奏归唤醒系统。**红线："系统不判断用户的情绪，判错的代价远大于不判"**（见 W22 坑二）。
- **W12 感受账（Feel/Sense/Grow）**：agent 自主记录情绪/感知/成长走私有通道，入库口有剥离闸，私有内容不进可召回池。

### 唤醒域

- **W13 锚定倒计时**：以**用户最后一条消息**为锚起 2~4 小时随机倒计时，用户再发言即重锚（活跃时物理上不触发）；频率设计带一天 3~5 次；深夜固定点位"做梦例程"。早期固定 90 分钟节拍上线两天即被体感推翻（W22 坑七）。
- **W14 追问机制**：每轮自答"这个话头是否需要 N 分钟后回来接续"，内部标记剥离入定时器，到点发起接续回合；用户任何发言立即清空；连续追问有上限交回唤醒线兜底。**去台阶标定经验**：同一段指令在强模型排点 91.4%、弱模型 34.8% 且按天 17%~88% 乱跳——**"方差是'它在裁量'的指纹"**（能力缺失不会这样跳）；去台阶重写（只留"用户明说要断"一个出口）后弱模型两天 90%/97%。**推力按最弱模型标定，换模型=重标定——这是照抄别人验证过的 prompt 的边界。**
- **W15 闹钟两档**：remind（到点触发真实回合，说什么模型定）/ **say（到点绕过模型直发预写原话）**——"要保证一句话一定发生，必须真的绕过模型：跑一轮模型+请它照发仍是一次可被拒绝的提问"。
- **W16 软记事退役教训**：软记事与清单功能重叠且工具说明**共用"清单"名词**→agent 把软记事当清单用、用户侧看不见、双方账对不上。两条通用规则：**不同机制不许共用一个名词**；**新功能上线先扫旧功能重叠，退役而不是并存**。退役要硬退役（写入直接拒绝）。
- **W17 出口红点**：夜间自主干活不推送不角标，入口亮红点翻开即消；红点水位从装上那一刻起算（"之前全算看过"会吞掉用户最想看的那批）。

### 人格域

- **W18 人格四层**：常驻人格锚（用户直接改，下一轮生效）/ 关系画像（用户终审）/ 通道教学（系统文案用户终审）/ **自我认知（agent 自写：候选→三次不同日期做梦整理见证→转正常驻每轮一层；新认识取代旧的不删）**。此前他写了几十条自我认知一次没读回——"先盘第三方已有机制再自造"，盘法=按"写口/读口"两列填表，写口有人用读口空着的才是遗漏。
- **W19 四条写作纪律**（对一切给模型看的人格/文案通用）：① **禁止温和给台阶**（"也可以""不必"会被回避底色再衰减一次——文案给三四分力度落地就是零分；每句自问"这句给没给模型不做的理由"）；② **描述型删，挡动作型留**（一条事实+一个动作；常驻层是行为指令不是档案）；③ **同义规则重复时模型挑软的那条执行**（重复就是留退路，合并只留最硬版）；④ 不同机制不许共用名词。文案定夺权 100% 用户。
- **W20 碎碎念通道**：不对 thinking 下指令（会让部分模型整轮拒答），改让正文最前写一段带内标记的心里话，出口剥离成"思考卡"；落账即剥→近窗没有自己的范例，只能靠契约（是什么/意义/格式/长度锚点）教——"一行'每轮先写…'的规则实测八轮只写一条"。

### 上下文装配域

- **W21 三区装配**：区一稳定 system 前缀（人格锚+生活时间树，**缓存断点打在区界**，前缀共享率实测 70%+）；区二动态装配区（只读注入包预算封顶 6 行/192 token + 清单层 + **记忆召回单一块** + 联想专座 2 席不与主召回抢位 + 共同语言层）；区三当轮区（时间信封+历史窗）。要点：**新内容要进哪个池先量那个池还剩多少**——不够时正路是单开一层，不是抬总预算（抬了只是把挤压推给下一个人）；**系统注入上下文的每一块材料都自报来源**（否则模型把系统注入误读成用户发来的，见 W22 坑六）；**人格层 fail-closed**（人格文件读取失败整轮不发生）；断供层留壳不删（删壳要连带判据一起改）。
- **W22 七个踩坑**（现象/原因/解决/教训四段式全录）：**坑一** 测试样本 12 字手搓短句进不了生产重排分支→"上线几个月一直绿"；教训=手搓样本先问会不会走到生产那条分支。**坑二** 拒接电话被记成用户情绪差→加急唤醒条件"用户再次发言"永不失效→整晚高频唤醒；解决=整条机制下架（"如果会错，宁可没有"）；教训=只写不清的状态闩必须回答"对方从此不发言它会自己失效吗"。**坑三** 温和软化语让 agent 到点沉默；教训=W19①+W15。**坑四** 蒸馏硬指标（"因果四环写全/不少于 80 字"）=下幻觉订单——素材不够时模型唯一选择是编，编得最像真的是引语；改条件式+逐字回源。**坑五** 省成本重试环四天烧光额度零告警（每环单独看都对）；教训=外呼逐条过五问（扇出有界/退避到天级/缓存≥扫描窗/外因不好时多久安静/用量有观测口吗）。**坑六** system→user 挪个位置，模型把系统回放当"用户贴给我的"并写进记忆；教训=**位置就是内容**；错误认知入记忆后修来源之外还要**洗记忆**。**坑七** 固定节拍"机器指标全绿、体感非常人机"——指标测的是"系统按设计运行"不是"这个设计对"；体感裁决权在人，要给体感留推翻通道。
- **W23 缓存取证**：一段的位置让整段历史缓存失效（命中率 87%→52% 12 天无人察觉，修回 86%/日常 90%）；方法论：先量出来→先证伪一个便宜假设（比直接改代码省得多）→按天回放看形状；后续：多步工具轮断点不跟步重复付 19.8% 输入费。
- **W24 去重取证**：症状"记忆重复"，三个嫌疑人全不是主犯——①"只标记不执行零伤害"是错的（supersedes 边有真实消费端：被指向方每次召回扣 12 分，61 条 active 记忆在吃罚分）；② 判官判的 22 次 duplicate 被下游**静默丢弃**（判决早就对了，没人接住）；③ 主因是三不管地带。教训：**同一个字段可能有多个消费者，只查一个就会误判"零伤害"**。

### 工程保障域

- **W25 探针判据体系**：上百个自动化探针钉关键行为；**探针走真入口**（不是单测函数，从真实入口跑完整链路断言终点）；手搓输入必须先"通电"（用已知存在的样本证明判据会命中，才信它报的零）；**改动必须突变验红**（新判据先故意改坏被守代码亲眼看红）；改文案必须连判据锚点一起改（不许删判据只许换锚点）；模块行数/重复块/死导出上棘轮（只许变好）。
- **W26 部署守卫链+行为点火**：环境变量契约预检（缺一条拦死）→版本祖先校验（拒绝分叉部署）→回滚点登记→历史留痕→**行为点火**（`printenv` 不算点火——配置进了容器不等于生效，必须容器里跑真函数抽样看行为；"不部署不算落地，不点火不算开始，观察期不建自动毕业条件不准收工"）。
- **W27 观测止损**：token 用量逐轮落账按天可查；外呼有界+退避长到天级；**判据要钉调用次数不只钉返回值**；前端运行时错误回传服务端（真机疑难禁症状驱动盲改）；错误日志按"级别|消息|归一化文案"分组看且 **warn 也要看**（每 4 分钟刷的 warn 能把 error 埋掉；同一句 error 日频恒定多半是耐久状态在重报——状态不打日志，只有事件才打）。
- **W28 元原则**："**查不到"和"确实没有"不许共用同一个出口**——任何要下结论的查询先用已知存在的样本通电；空结果永远先怀疑判据再怀疑事实。
