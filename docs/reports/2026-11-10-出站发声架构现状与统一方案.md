# 出站发声架构现状审计与统一方案

> 日期：2026-11-10
> 触发：用户报障——同一条消息线被拆成多段、跨时段碎片续话，「不像一个独立的个体」。
> 用户裁决：**执行架构统一**；先完整认清现状，再动代码。
> 取证来源：仓库代码实况（HEAD `528644e`）+ 生产 `chat_history` / `agent_plane.db` / `app.log`。
> 状态：**仅审计与设计，零代码变更**。

---

## 0. 一句话结论

当前系统不是「一个角色在说话」，而是 **4 个独立生产者 + 1 条人工通道**，共用一份只读历史、各用一套 prompt、各自决定何时开口。
共享的只有**内容过滤器**（`terminal_reply_guard`）与**落库函数**；没有共享的**发声者、意图、承诺、线程归属**。

所以「不像一个独立个体」不是文风问题，是**结构事实**：它确实由多个程序分头发声。

## 2. 逐线拆解

### 2.1 主链回复线（被动应答）

- **入口**：`wechat_connector._handle_message_serial`（入站配额 → 幂等认领 → `_peer_lock` 串行）。
- **决策**：编排器 `orchestrator/optimized_orchestrator.py`；L0/L1 工具闸 + 主链 tool loop；`_finalize_reply` 终裁。
- **人设/prompt owner**：`shisi/application/persona_service.py::build_system_prompt` + `shisi/core/models/character_aggregate.py::build_system_prompt`；回复模式由 `utils/reply_mode` 决定。
- **上下文槽**：人设、`[MM-DD HH:MM]` 逐行历史、记忆槽、`topic_state` 快照、RAG、`[主动]`/`[定时提醒]` 出站标记（`context_budget.annotate_outbound_markers`）。
- **表达**：`publish` → `send_reply_segments` → `split_reply_for_wechat`：
  - **带换行就必须拆**（哪怕总长短）；单行 ≤45 字才不拆；
  - `max_segments` 取值 **2/3/4**（`utils/humanize_config.py:83`，**没有 1**）；
  - 段间延时 0.4–1.6 s（dynamic 档）。
- **记账**：`memory_pipeline.write_chat_history_sync` / `after_chat`。

### 2.2 主动决策线

- **前置闸**（顺序）：角色解析 → `paused` / `enabled` → 静默时段 → 首选模型熔断 → 微信 token 窗口（只拦确证 dead）→ 节奏双闸（`min_interval` / 回复后冷却）→ `should_skip_proactive_decision` → 连击闸。
- **上下文**（`build_proactive_context`，`proactive/llm_proactive.py:760+`）：
  1. 完整人设 `proactive_context.load_full_persona_hint`（**另一套渲染器**，≤1200 字）
  2. 画像 `get_profile_prompt_block`（主链同款）
  3. 记忆事实（`_proactive_memory_facts`）
  4. **【上次决定的下一步】**（`topic_plan`）
  5. 【用户最后一句】/【最近互动热度】/最近话题
  6. **【当前角色最近对话原文】**（最近 14 条，含 `proactive=true` 标记 + 时间戳）
  7. **【之前没聊完的事】**（parked 话题，≤2 条）
  8. hooks（未答问题 / 将到提醒 / **用户承诺未闭环** / 热点）
  9. 知识库/热点
- **决策**：`decide_proactive`，17 条硬规则；输出 `should_contact / message / reason / wait_minutes / next_topic / next_intent / voice`。
- **后置闸**：`is_duplicate_proactive`（同文）→ `post_draft_judge`（fail-closed，只判发/不发）。
- **投递**：`_deliver`（`terminal_reply_guard` → judge → 文字/语音 → `_record_outbound(channel=proactive)`）。
- **自喂结构**：`topic_plan` 只被主动线读写；主链完全看不到它。

### 2.3 提醒线

- 每分钟 tick，**确定性**投递；文案在投递前由 LLM 按角色口吻生成（失败引用用户原话）。
- **豁免静默时段**（叫醒类）；失败 3 次判 failed。
- 记账 `channel=reminder`。

### 2.4 重要日期线

- 每小时；画像生日（公历+农历）+ 角色级日期；LLM 生成、模板兜底；当日幂等键带 `user_key`；定向投递。

### 2.5 控制命令线

- 每 5 秒消费跨 worker 持久命令；管理员手动发送；走 `_deliver`（同一守卫/judge）。

## 4. 断裂点清单（全部带生产实证）

### F1｜同一句话被两个决策器分着说完（本次报障）

- 09:23:33 主链一条回复：`那就别硬逼…把能拿的分拿了。\n我这边有之前整理的笔记，你要是现在方便发我看看，我帮你理理思路`
- `split_reply_for_wechat` 因含换行拆成 2 条 → 截图最上面两个气泡（相隔约 1.5 s）。
- 10:24:40 主动线接着说了另外半句：`别全背，先过一遍这个。`
- **根因**：主链只负责"回这一句"，主动线只负责"找由头开口"；两线没有任何「这半句谁接着说」的归属状态。

### F2｜主动线自喂自己的输出

- 决策 reason 原文（10:24）：`由头是【之前没聊完的事】里角色主动提出帮用户整理笔记的后续`
- 17:35：`基于【上次决定的下一步】…分享旧书内容作为由头` → 实际产出 `发给你看看 就当换换脑子`
- 19:35：`原计划若用户未回应笔记则在20:00左右切入…由头具体为"之前整理的笔记"及"标出的重点"`
- 19:25 还有一次 `哪怕只看一眼也行` 投递失败后 19:35 换文案重发。
- **一个念头在 9 小时内被拆成 3 次独立发言**，每次都是新决策，每次都不知道上一次其实什么也没交付。

### F3｜没有能力模型：承诺了系统做不到的事

- 系统只有 `send_voice_clip` / `send_image`（且后者不在主动线文字通道），**没有任何发文件/笔记的通道**。
- 但生成侧可以自由说「发给你看看」「我标了几处重点」——**承诺永不兑现**。

### F4｜没有承诺账本

- 全仓无「我说过要发 X / 是否已兑现 / 过期时间」的表或状态。
- `proactive_hooks` 的"未闭环承诺"只查 **用户** 的 commitment 事实，**不查角色自己的承诺**。
- `post_draft_judge` 规则 4 判"编造承诺"，但历史里确有那句话，所以判不出"承接未兑现承诺"。

### F5｜措辞多头

- 主链人设：`persona_service.build_system_prompt` + `character_aggregate.build_system_prompt`
- 主动线人设：`proactive_context.load_full_persona_hint`（不同渲染、不同截断上限）
- 提醒线：自己的 `system_prompt` 片段
- 日期线：模板 + LLM
- 同一张角色卡被 4 条代码路径各渲染一次 → 口吻天然漂移。

### F6｜表达层再切一刀

- 主链回复按换行拆 2–4 条 + 0.4–1.6 s 延时；`max_segments` 最小为 2，用户无法关掉。
- 这一层单独看是"拟人"，叠在 F1 上就变成"一句话被切两次"（一次跨线、一次跨气泡）。

### F7｜历史只有"内容"，没有"意图 / 线程归属 / 未完成状态"

- 主链看不到 `topic_plan`；主动线看不到主链"话说到一半"的状态。
- `chat_history` 只存最终文本 + `channel`，不存"这句是承诺/这句待续/这句对应哪个话题"。

### F8｜记账粒度不一致

- 主链按 turn 落库；主动线按单条落库（`channel=proactive`）；提醒线 `channel=reminder`；广播线无 session。
- 同一"对话"在库里的形态因生产者而异，后续任何统一分析/回放都要分线特判。

## 5. 目标架构：单一发声者（Speaker）

### 5.1 概念模型

**一个角色 = 一个 Speaker 实例**（键：`user_key × character_id`）。
所有"想说"的东西都只是**意图**，不是消息：

```
UtteranceIntent {
  source: REPLY | PROACTIVE | REMINDER | IMPORTANT_DATE | MANUAL
  session_key, character_id
  payload: {user_msg?, reminder?, date?, plan?}
  priority, deadline, created_at
}
```

Speaker 负责：**裁决 → 起草 → 过闸 → 投递 → 记账 → 更新状态**。

```
intent ──► arbitrate（此刻该不该说 / 是否合并 / 是否延后）
       ──► compose（唯一人设 + 唯一历史 + 开放线程 + 承诺账本 + 能力清单）
       ──► express（是否拆条、延时、语音/文字）
       ──► guard（terminal_reply_guard + judge）
       ──► deliver（唯一投递接口）
       ──► record（chat_history + channel + thread/commitment 更新）
```

### 5.2 四个共享件（缺一不可）

| 共享件 | 作用 | 替代物 |
|---|---|---|
| **PersonaContext** | 唯一人设渲染，所有线共用一份 | 两套 `build_system_prompt` / `load_full_persona_hint` |
| **ThreadState** | 「我现在这个话题说到哪、还有没有半句话没说完」 | 主动线的 `topic_plan` 自喂 |
| **CommitmentLedger** | 「我说过要做什么、做了没有、什么时候过期」 | 无（新增） |
| **CapabilityModel** | 「我实际能发什么」→ 生成侧硬约束 | 无（新增） |

### 5.3 关键裁决（设计选择）

1. **主动线保留独立决策，但不再独立发声**：它只产出 `UtteranceIntent(PROACTIVE)`，由 Speaker 统一选上下文与措辞。
2. **提醒/日期是"能力"，不是"另一个我"**：它们产出 `UtteranceIntent(REMINDER/IMPORTANT_DATE)`，Speaker 用同一人设口吻说出来；时间点仍由确定性调度决定。
3. **拆条归表达层**：是否拆、拆几条、间隔多久，由 Speaker 一处决定；`max_segments` 放开 `1` 作为"永不拆"。
4. **承诺必须落账**：任何出站文本里出现"我发你/给你/传你/稍后告诉你"等交付语义，写入 `CommitmentLedger`；未兑现期间，任何线不得再以它为"由头"；到期自动关闭。
5. **能力驱动的生成约束**：`CapabilityModel` 只暴露 text/voice/image；生成侧明确"不能发文件/链接"，从源头消除空头承诺。

### 5.4 与现有代码的落点

| 现状 | 迁移后 |
|---|---|
| `wechat_connector.publish` 直接拆条发送 | 提交 `REPLY` 意图 → `Speaker.speak` |
| `scheduler._llm_proactive_one_user` 决策后直接 `_deliver` | 决策后提交 `PROACTIVE` 意图 → `Speaker.speak` |
| `reminder_delivery._compose_text` 自己拼 prompt | 提交 `REMINDER` 意图 → `Speaker.compose` |
| `_check_important_dates` 自己生成 | 提交 `IMPORTANT_DATE` 意图 |
| `_drain_control_commands` | 提交 `MANUAL` 意图 |
| `topic_plan` 自喂 | `ThreadState`（含 open/closed/owner） |
| 无承诺状态 | `CommitmentLedger` 表 |

## 6. 分批迁移（每批可独立回滚）

| 批 | 内容 | 行为变更 | 回滚 |
|---|---|---|---|
| **B1 基础件** | 新建 `Speaker` 骨架 + `PersonaContext`（先只读、旁路对比）+ `CommitmentLedger` 表 + `CapabilityModel` | 无（影子模式） | 删除新模块即可 |
| **B2 主动线上收** | 主动决策改为提交意图；`topic_plan` 由 `ThreadState` 取代；承诺未兑现禁止续提 | 本次碎片续话消失 | `SPEAKER_PROACTIVE=0` |
| **B3 主链上收** | 主链走同一 `PersonaContext` + `ThreadState`；一条回复不再按换行硬拆 | 一句话不再被切两段 | `SPEAKER_REPLY=0` |
| **B4 能力线收编** | 提醒/日期/手动全部经 `Speaker.compose`；拆条归表达层；`max_segments=1` 可选 | 全站一个口吻 | 逐线开关 |

每批门槛：红测先行 → 受影响面回归 → 四分块全量 → `ruff` → 生产冒烟 → 部署，基线数字按 `AGENTS §4.3` 声明卡数与工作树状态。

## 7. 需要裁决的开放问题

1. **提醒/日期是否允许"不像角色"**：它们是功能承诺（"叫你起床"），必须送达；是否允许 Speaker 改写口吻，还是保留模板原文？
2. **主动线的独立性**：统一后主动线仍可自判"说不说"，但它的"由头"必须来自 `ThreadState`/`CommitmentLedger`/hooks，不能来自自己的上一条计划——是否接受这个收紧？
3. **`max_segments=1`**：是否放开"永不拆条"作为用户可选项（当前最小 2）？
4. **旧路径退役**：`topic_plan` 表、`ase_engine` 状态是否在 B2/B3 后删除（需 `DELETION_LOG` 登记）？
