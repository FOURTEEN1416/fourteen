### P0.5（新增 — 0.5 人天）

#### P0.5: 主动消息通道修复
> ★ 原方案遗漏的spec第10方向，补全

**问题**: ProactiveScheduler中 `_ws_server` 和 `_wechat_connector` 在 `__init__` 中被硬编码为 `None`(scheduler.py:58-59)，导致connect方法无实际连接可初始化。

**方案**: 通道注册模式（内部dict，不过度拆分）

```python
# proactive/scheduler.py 改造

class ProactiveScheduler:
    def __init__(self, ...):
        # self._ws_server = None  ← 删除
        # self._wechat_connector = None  ← 删除
        self._channels: dict[str, Callable] = {}  # 通道工厂注册表
    
    def register_channel(self, name: str, sender_factory: Callable):
        """注册消息通道"""
        self._channels[name] = sender_factory
    
    def connect_channel(self, name: str):
        """初始化通道连接"""
        factory = self._channels.get(name)
        if factory:
            return factory()
        raise ValueError(f"Unknown channel: {name}")
    
    async def _send_to_all(self, message: str):
        """向所有已注册通道发送消息"""
        for name, factory in list(self._channels.items()):
            try:
                channel = factory()  # 懒初始化
                await channel(message)
            except Exception as e:
                logger.warning(f"通道 {name} 投递失败: {e}")
                # 标记失效，触发健康检查
    
    async def _health_check(self):
        """每60s检查通道健康"""
        for name in list(self._channels.keys()):
            try:
                # 尝试发送心跳
                await self._send_to_channel(name, "__ping__")
            except Exception:
                logger.error(f"通道 {name} 断开，等待重连...")
```

**集成位置**: main.py 中创建 ProactiveScheduler 后注册通道

**验收标准**:
- start() 后通道连接状态为 active
- 微信失败自动降级到 WebSocket → Console
- 每60s健康检查，断连自动重连
- 免打扰时段(23:00-07:00)不投递非紧急消息

#### P1-3: 上下文智能压缩（0.5人天）
> 原3.3节，简化：仅LLM摘要 + template fallback

```python
# conversation_summarizer.py 改造

class SmartCompressor:
    """
    2级降级: LLM摘要 → template摘要
    """
    def __init__(self, llm_gateway, keep_recent=20):
        self.llm = llm_gateway
        self.keep_recent = keep_recent
    
    def compress(self, messages: List[dict]) -> tuple:
        """返回 (recent_messages, summary_str)"""
        if len(messages) <= self.keep_recent:
            return messages, ""
        
        old = messages[:-self.keep_recent]
        recent = messages[-self.keep_recent:]
        
        # 1级: LLM摘要
        summary = self._llm_summarize(old)
        if summary:
            return recent, summary
        
        # 2级(降级): template摘要
        return recent, self._template_summarize(old)
```

**关键变更**:
- ❌ 移除 AGGRESSIVE 模式（项目中无适用场景）
- ✅ 保留 LLM + template 两级（够用但能落地）
- ✅ template fallback：提取关键词+话题+情感标签

```python
# emotion_engine.py ContinuityGuard.check_transition() 改造

def check_transition(self, old_emotion: Emotion, new_emotion: Emotion) -> bool:
    """
    情感转移检查
    策略：白名单覆盖（保留原始8条）+ 规则推断（其余92条）
    """
    key = (old_emotion, new_emotion)
    
    # 白名单覆盖（原始8条，保持不变）
    if key in EMOTION_TRANSITION_MATRIX:
        prob = EMOTION_TRANSITION_MATRIX[key]
    else:
        # 规则推断：基于愉悦度距离
        delta = abs(EMOTION_PLEASURE_MAP[old_emotion] - EMOTION_PLEASURE_MAP[new_emotion])
        # 距离越近，转移概率越高
        prob = max(MIN_TRANSITION_PROB, 1.0 - delta / 2.0)
    
    return random.random() < prob
```

**关键变更**:
- ❌ 不硬编码100条转移对（维护成本高，易出错）
- ✅ 规则驱动：愉悦度距离法（1天覆盖100%转移）
- ✅ 保留原始8条特例覆盖规则（向后兼容）
- ✅ 行归一化天然满足（动态计算，无需手动维护）

**验收标准**:
