## 0. 结论摘要

1. **（Q0 通过后）部署形态单一推荐：首版生产走 Breeze 托管 API**。理由：现生产是 Linux CPU-only（4–8GB RAM、`.venv-cpu`、4 worker，无 GPU 记录），自托管 Breeze 需 12–24GB NVIDIA GPU 且权重为非商用许可；托管 API 是唯一「不新增硬件 + 付费计划输出可商用」的生产路径（《Breeze 调研》§2.4/§3.2/§3.3）。
2. **（Q0 通过后）角色定位推荐：MiMo 保持默认主力，Breeze 作为按角色 opt-in 的高质量引擎；Breeze 失败回落 MiMo，MiMo 失败不自动回落付费 Breeze**。这样质量增益可控、成本不会因一次故障无声放大。
3. **集成面很小**：Breeze 托管默认输出 mp3，可直接进既有 `SynthesizedAudio(fmt="mp3")` → `voice_result_payload` → `coerce_voice_payload` → `AudioFormatConverter.to_silk`（失败 `to_amr`）→ `send_voice` 链，首版不改 orchestrator 的语音调用形态（《测绘》§1.1/§1.8；《Breeze 调研》§4.2）。
4. **真正要改的是四块**：① 新增 `voice/breeze_tts_provider.py`；② `TTSManager` 从「单引擎 + 失败永久切引擎」改为「多引擎注册 + 按调用路由 + 回退链 + 冷却」；③ `engine/model/voice_id` 三层白名单从 MiMo 单值扩展为「按引擎分域」；④ `CharacterVoiceSpec`/`VoiceCatalog` 增加 engine 维度（旧 JSON 默认 `mimo-tts`，无迁移）。
5. **两个硬门必须先过**：商业许可/数据跨境（托管 API 付费计划输出可商用，但免费计划 FAQ 明确不可商用；参考音频/文本发美国公司需 PIPL 评估）与生产到 `api.breeze.blue` 的中国网络实测（公开文档无区域承诺）。未过门之前 `breeze-tts.enabled=false`，代码合入但不启用。此外 **Q0（是否引入/是否修订 AGENTS L6）未书面确认前，本文只作候选设计**，不得据此改生产配置或删除「MiMo 唯一引擎」的现行文档口径。

### 1.6 与 MiMo 的关系（Q0 通过后的口径；Q0 未过则维持 MiMo-only）

- **不是替换，是共存**：MiMo 继续作为默认主力（当前限时免费、国内平台、中文原生），Breeze 作为按角色 opt-in 的高质量引擎。
- **Q0 通过后不再用「唯一引擎」措辞**：`voice/__init__.py` docstring、`voice/tts_manager.py:60-62`、`config/system.yaml:141`、`api/routers/voice_routes.py:118-123` 的「唯一引擎」需同步改为「默认引擎 + 可选引擎」。这是 Q0 裁决后的文档落点，属 B 档（文档）与 A 档（配置/API）分别提交；Q0 未过时保持原文。
- **SAPI 不是 Linux 生产兜底**：`MiMoTTSProvider` 的本地兜底只在 `win32` 生效（`voice/mimo_tts_provider.py:320-322`）；任何云端 TTS 方案都不能把 SAPI 当生产降级路径（《Breeze 调研》§4.2 第 9 条）。

### 2.2 单一推荐

> **首版生产：Breeze 托管 API（F）。**
>
> **理由**（按权重排序）：
> 1. **宿主门**：现生产 Linux CPU-only、4–8GB RAM、无 GPU 记录（`deploy/README.deploy.md:14-16`；`docs/HANDOFF_REPORT.md:9`），自托管 Breeze 需 12–24GB NVIDIA GPU；不新增硬件是唯一能立即落地的路径（《Breeze 调研》§3.2①/§3.3）。
> 2. **许可门**：托管 API 的付费计划输出可商用；自托管权重是非商用许可，商用还要 BreezeBlue 书面许可（《Breeze 调研》§2.4）。托管 API 把「代码许可」和「权重许可」两件事合成一份商务合同，路径更短。
> 3. **接入面**：Breeze 托管默认 mp3，现有 `SynthesizedAudio(fmt="mp3")`、`voice_result_payload`、`AudioFormatConverter.to_silk` 全部可复用，首版不需要改 orchestrator 的「整段回复后合成」形态（《测绘》§1.1/§1.8；《Breeze 调研》§4.2）。
> 4. **可回退**：托管 API 失败可回落 MiMo（国内、当前免费），不会把主链拖死；自托管 GPU 故障则是整条语音链断。
>
> **不推荐作为首版生产**：自托管 A/A′/B/C/D/E。C/D 只用于开发机试听与批量预生成；A/B 只有拿到 BreezeBlue 商业许可且新增 GPU 机器后才进入候选。

### 2.3 关键假设与验证步骤（未验证前不得当事实）

| 假设 | 内容 | 验证步骤 | 不成立时的处理 |
|---|---|---|---|
| **A1** | 官方 API Reference（2026-10-27 抓取）`POST /v1/text-to-speech/{voice_id}` 的 body **支持可选 `model_id`**（1–120 字符）与可选 `language_code`（两字母 ISO 639-1）；`model_id` 省略时服务端自动选择，且 TTS guide 明确「显式 `language_code: en/zh` 选 `breeze-tts-2`，其他或省略语言选 `breeze-tts-2-multilingual`」。因此**不能依赖默认**：provider 必须显式发送 `model_id`，并显式发送 `language_code: zh`；否则 `breeze_model` 不生效，未显式传语言时还会被自动选成 multilingual，造成音色/模型不匹配 | 用试用 key 按官方文档 curl `POST /v1/text-to-speech/{voice_id}?output_format=mp3`，分别验证 ① 显式 `model_id=breeze-tts-2` + `language_code=zh`；② `model_id=breeze-tts-2-multilingual` + `language_code=zh`；③ 不兼容的 model/language 组合必须报错；核对请求体/响应头/错误码 | 若字段名或取值变更，按实测修正；`model_id` 不可用时才回退到「显式 `language_code`」策略，并在 provider 日志标注实际模型 |

## 3. 集成设计

### 3.1 总体架构

```
orchestrator.process_message
  └─ CharacterVoiceSpec.synth_kwargs()  →  {engine, model, voice_id, instructions, speed, pitch}
      └─ TTSManager.synthesize(text, emotion, **kwargs)
          ├─ 解析 engine（per-call 覆盖，默认 voice.engine）
          ├─ 路由链：engine → voice.routing[engine].fallback
          ├─ provider.synthesize()（Breeze / MiMo）
          └─ 失败：冷却 + 回落；engine-scoped kwargs 不跨引擎透传
              └─ SynthesizedAudio(fmt="mp3"|"wav")
                  └─ voice_result_payload → 微信 coerce → to_silk/to_amr → send_voice
```

**职责边界**：
- `TTSManager` 只做「注册/路由/降级/健康」，不做音色解析。
- `CharacterVoiceManager` 只做「角色 → 不可变快照」，不决定引擎默认。
- `BreezeTTSProvider` 只做「一次 HTTP 合成」，不读写全局状态、不做跨引擎回退。
- `orchestrator` 只决定「要不要语音」，不拼 provider 参数。

### 3.2 新 Provider：`voice/breeze_tts_provider.py`

**契约**：实现 `TTSProviderBase`（`voice/tts_provider_base.py:18-74`），`synthesize(text, **kwargs) -> SynthesizedAudio | None`，`health_check() -> dict`，`name = "breeze-tts"`，`supports_streaming = False`（首版；托管 stream 存在但主链未消费，不虚报能力）。

**实现要点**：
- HTTP 用 `aiohttp`（项目已有依赖 `pyproject.toml:35`），不引入官方 `breeze-blue` SDK；理由：只需要两个端点（TTS + 可选 voice 注册），SDK 会增加依赖与版本耦合，且现有 MiMo provider 就是 aiohttp 直连（`voice/mimo_tts_provider.py:23,189-194`）。
- 端点：`POST {base_url}/text-to-speech/{voice_id}?output_format=mp3`；鉴权 `xi-api-key: <key>`（或 `Authorization: Bearer`，二选一，首版用 `xi-api-key`，与官方文档一致；《Breeze 调研》§2.5）；请求头加 `Accept: audio/mpeg`。
- 请求体：`text`（必填）、`model_id`（本设计必须显式发送：优先 `breeze_model`，空则引擎默认 `breeze-tts-2`）、`language_code: "zh"`（显式，避免服务端在未给语言时自动选 `breeze-tts-2-multilingual`）；`voice_id` 走 path；`output_format` 走 query。**`model_id` 不是本地能力标注，它决定实际模型，禁止省略。**
- 参数映射（不得静默丢弃）：`emotion` → `instructions`（按 `MiMoTTSProvider.EMOTION_MAPPING` 的 9 个中文情感标签生成短导演指令，如 开心→「语气轻快、带笑意」、伤心→「语气低落、稍慢」；角色级 `breeze_instructions` 优先并可拼接）；`speed` → `voice_settings.speed`（钳制 0.5–2.0，越界记 warning 后钳制）；`pitch` 无 Breeze 对应字段，折入 `instructions`（如「音调略高」）或标记 `tts_param_unsupported`，不得静默丢弃。参数全部来自调用快照，provider 不写实例状态。
- 响应：HTTP 200 且 `bytes` 非空 → `SynthesizedAudio(data, fmt="mp3")`；空体按失败处理（对齐 MiMo `_last_error="API 返回空音频"` 的惯例，`voice/mimo_tts_provider.py:195-204`）。
- 错误映射：401/402/403 → `last_error` 记录鉴权/余额；429 → 读 `Retry-After`，最多重试 1 次；503/504 → 直接失败；所有失败返回 `None`，由 manager 回退。
- 并发：`asyncio.Semaphore` 只能限制**单进程**；生产是 4 worker（`deploy/ai-girlfriend.service:14-21`），账号级并发 = 每进程上限 × worker 数。配置改以 `account_max_concurrency`（套餐值）为真源，按 `worker_count` 派生 `max_concurrency_per_process = max(1, account_max_concurrency // worker_count)`；例如 Starter 4 / 4 worker → 每进程 1，而不是 2。若套餐并发 < worker 数（Free 2 / 4 worker），必须启用跨进程共享限流：可选 ① 本地文件锁租约（复用 `orchestrator/session_locks.py` 的 fcntl/msvcrt 锁模式，按租约令牌计数）；② 单进程本地 TTS 网关（localhost HTTP 队列，所有 worker 只投递任务）。也可临时降 `--workers`。否则仅靠进程内信号量会把账号级并发放大到 8/32 并触发 429。`max_concurrency` 不再作为可手填的每进程值。
- 文本上限：1000 字符/请求；本仓主链 `reply[:200]`（`orchestrator/optimized_orchestrator.py:2064`），远低于上限；provider 仍做 `len(text) > 1000` 拒绝并记 warning，避免未来直连接口绕过。
- 不写实例状态：`voice_id`/`model` 全部从 kwargs 解析；并发多角色不串音（沿用 W7 契约，`voice/tts_provider_base.py:36-39`）。

**代码骨架（设计示意，不是最终实现）**：

```python
class BreezeTTSProvider(TTSProviderBase):
    SUPPORTED_MODELS = ["breeze-tts-2", "breeze-tts-2-multilingual"]

    def __init__(self, api_key: str, base_url: str = "https://api.breeze.blue/v1",
                 model: str = "breeze-tts-2", voice_id: str = "",
                 timeout: float = 15.0, max_concurrency_per_process: int = 1):
        self._api_key = api_key
        self._base_url = base_url.rstrip("/")
        self._model = model if model in self.SUPPORTED_MODELS else "breeze-tts-2"
        self._voice_id = voice_id
        self._timeout = timeout
        self._semaphore = asyncio.Semaphore(max(1, int(max_concurrency_per_process)))
        self._last_error: str | None = None

    @property
    def name(self) -> str:
        return "breeze-tts"

    @property
    def supports_streaming(self) -> bool:
        return False

    async def synthesize(self, text: str, **kwargs) -> SynthesizedAudio | None:
        voice_id = str(kwargs.get("voice_id") or self._voice_id or "")
        if not voice_id:
            self._last_error = "未配置 Breeze voice_id"
            return None
        if len(text) > 1000:
            self._last_error = "文本超过 Breeze 1000 字符上限"
            return None
        model_id = str(kwargs.get("model") or self._model or "breeze-tts-2")
        if model_id not in self.SUPPORTED_MODELS:
            model_id = "breeze-tts-2"
        body: dict[str, Any] = {
            "text": text,
            "model_id": model_id,          # 必须显式：省略会按 language_code/默认自动选型
            "language_code": "zh",
        }
        speed = _clamp_speed(kwargs.get("speed"))
        if speed is not None:
            body["voice_settings"] = {"speed": speed}
        instructions = _build_instructions(kwargs.get("emotion"), kwargs.get("pitch"),
                                           kwargs.get("instructions"))
        if instructions:
            body["instructions"] = instructions
        try:
            async with self._semaphore:
                async with aiohttp.ClientSession(timeout=aiohttp.ClientTimeout(total=self._timeout)) as session:
                    async with session.post(
                        f"{self._base_url}/text-to-speech/{quote(voice_id)}",
                        params={"output_format": "mp3"},
                        json=body,
                        headers={"xi-api-key": self._api_key},
                    ) as resp:
                        if resp.status != 200:
                            self._last_error = f"HTTP {resp.status}"
                            return None
                        data = await resp.read()
                        if not data:
                            self._last_error = "API 返回空音频"
                            return None
                        self._last_error = None
                        return SynthesizedAudio(data=data, fmt="mp3")
        except Exception as e:
            self._last_error = str(e)
            return None
```

> 注：`aiohttp.ClientSession` 每次新建会带来连接池开销；最终实现建议在 provider 内持有一个懒加载 session + `close()`，或在 manager 生命周期内复用。设计骨架只表达契约，不锁定实现细节。`_clamp_speed()` 把 `speed` 钳制到 Breeze 的 0.5–2.0 并记录越界 warning；`_build_instructions()` 把 `emotion`（9 个中文情感标签）与 `pitch` 折成短导演指令，角色级 `breeze_instructions` 优先。

### 3.3 `TTSManager` 改造（多引擎注册 + 路由 + 回退链）

现状问题（逐条对应代码）：
1. `initialize` 只注册 `mimo-tts`，无 MiMo key 整个管理器禁用（`voice/tts_manager.py:63-85`）——Breeze-only 部署会直接不可用。
2. `synthesize` 失败后遍历其他 provider，成功即 `_current_engine = name`（`:141-151`）——**一次瞬时 429 会永久降级到 MiMo，Breeze 永不恢复**；现有测试 `tests/test_voice_manager.py:169-178` 钉住了这个旧语义。
3. 没有按调用选择引擎的能力——`CharacterVoiceSpec.engine` 不进入 kwargs（`shisi/voice/character_voice.py:52-64`）。

**改造方案**：

| 能力 | 设计 |
|---|---|
| 注册 | 维护 `_ENGINE_SPECS = {"mimo-tts": MiMoTTSProvider, "breeze-tts": BreezeTTSProvider}`；按 `config[engine].enabled` + `api_key` 注册；任何引擎缺失只 warning，不整体禁用，除非所有引擎都不可用 |
| 默认引擎 | `voice.engine` 仍为默认（首版 `mimo-tts`）；`switch_engine` 保留 admin 手动切换 |
| 按调用路由 | `synthesize` 先 `requested = kwargs.pop("engine", None)`；`primary = requested or self._current_engine`；`chain = [primary] + routing.get(primary, [])` |
| 回退 | 逐 provider 尝试；**不回写 `_current_engine`**；记录 `last_engine_used`；失败引擎进入 `degraded_until`（冷却，默认 60s），冷却期内跳过 |
| 回退参数清理 | 跨引擎回退时丢弃 `model`/`voice_id`/`speaker_name`/`instructions`（引擎域参数）；`emotion/speed/pitch` 不是原样透传，而由每个 provider 各自翻译（MiMo→speed/pitch 比例；Breeze→`voice_settings.speed` + `instructions`，pitch 无直接字段则折入 instructions 或标记 `tts_param_unsupported`），避免把 Breeze voice_id 传给 MiMo 或把 MiMo 预设名传给 Breeze |
| 健康 | `health_check` 增加 `routing`、`last_engine_used`、`degraded`、`degraded_count`、`last_degraded_reason`、每引擎 success/fail 计数 |
| 旧测试 | `tests/test_voice_manager.py:169-178` 由「assert 永久切换」改为「assert `last_engine_used=="fallback"` 且 `current_engine` 不变」；新增「冷却后恢复主引擎」用例 |

> **兼容性**：如果某部署只配置 MiMo，`routing` 为空，行为与现状等价（唯一 provider）；如果只配置 Breeze，`voice.engine="breeze-tts"`，也不会因缺 MiMo key 整体禁用。

### 3.5 `CharacterVoiceSpec` 与 `voice_catalog` 适配

**`CharacterVoiceSpec`（`shisi/voice/character_voice.py:41-64`）**：
- 新增字段 `breeze_model: str = ""`、`breeze_instructions: str = ""`；保留 `mimo_model` 不变；`engine` 默认 `mimo-tts`。
- `synth_kwargs()` 改为（**引擎域分派，`speaker_name` 永不进入 Breeze**）：

  kwargs = {"engine": self.engine or "mimo-tts"}
  if self.engine == "breeze-tts":

          kwargs["model"] = self.breeze_model

- **Breeze 绑定只认 `voice_id`**；`speaker_name` 继续只服务 MiMo 预设/SAPI 本地发音人，不参与 Breeze 合成（避免把 MiMo 预设名当 Breeze voice_id 发送）。
- `bind_voice()` 不变（kwargs 展平落盘），因此旧 `data/character_voices.json` 零迁移；新字段只在绑定时写入。
- `engine` 校验：`CharacterVoiceManager.bind_voice` 目前不校验 engine（只存字符串）。建议在 API `_validate_contract` 校验，manager 保持纯存储（避免两处白名单）。

**`VoiceCatalog`（`voice/voice_catalog.py:40-144`）**：
- **唯一键必须是 `(engine, voice_id)`**：`register(engine: str, voice_id: str, ...)` 内部写 `self._entries[(engine, voice_id)] = entry`（不是 `_entries[voice_id]`，现状见 `voice/voice_catalog.py:108`）。磁盘 JSON 用 `{"engine::voice_id": entry}` 或嵌套 `{engine: {voice_id: entry}}` 表示；无论选哪种，读写都必须经同一序列化函数，禁止两套键形（防 v1.56 R7 键漂移）。
- `get(voice_id, engine: str | None = None)`、`remove(voice_id, engine)`：有 engine 时按 `(engine, voice_id)` 精确匹配（旧条目无 engine 视为 `mimo-tts`）；无 engine 只保留给迁移/诊断，生产调用点必须传 engine。
- `is_known(voice_id, engine=None)`：`engine="mimo-tts"` 时允许静态预设 + catalog；`engine="breeze-tts"` 时只允许 catalog 中 `engine="breeze-tts"` 的条目，不把 MiMo 预设当 Breeze 音色。
- **所有现有调用点必须补 engine**，否则跨引擎同 id 会互相覆盖或被 MiMo 误接受：`api/routers/voice_routes.py:129`（`is_known`）、`:300`（`list`）；`api/routers/mimo_voice_routes.py:145`（`register`）、`:332`（`is_known`）、`:468`（`get`）、`:484`（`is_known`）。MiMo 侧统一传 `engine="mimo-tts"`，Breeze 侧传 `engine="breeze-tts"`；新增测试必须覆盖「同一 voice_id 在两个引擎各有一条，互不覆盖、互不通过对方校验」。
- `presets_for(engine)`：MiMo 返回 3 个静态预设；Breeze 返回空（首版没有内置预设，必须先在 Breeze 控制台创建/设计并登记）。
- `list(engine=None)`：支持按引擎过滤，供 `/api/voice/speakers` 使用。

### 3.8 主备/分流与失败降级链

**首版路由（推荐）**：

| 场景 | 主引擎 | 回退链 | 说明 |
|---|---|---|---|
| 未绑定角色的普通会话 | `mimo-tts` | `[]` | 保持现状，零行为变化 |
| 绑定 `engine="mimo-tts"` 的角色 | `mimo-tts` | `[]` | 同上 |
| 绑定 `engine="breeze-tts"` 的角色 | `breeze-tts` | `["mimo-tts"]` | Breeze 质量优先；失败回落 MiMo，用户仍听到声音 |
| 全局 `voice.engine="breeze-tts"`（若用户选择 B 方案） | `breeze-tts` | `["mimo-tts"]` | 全量切换时必须显式改配置，不是默认 |

**失败降级路径（逐跳）**：
1. Breeze `401/402/403` → 配置/余额错误，记 `tts_quality_degraded reason=auth/credit`，**不重试**，回落 MiMo。
2. Breeze `429` → 读 `Retry-After`，最多重试 1 次；仍 429 → 回落 MiMo，并记 `reason=concurrency`。
3. Breeze `503/504` / 超时 / 空音频 → 回落 MiMo，记 `reason=capacity/timeout/empty`。
4. MiMo 失败 → 走 MiMo 内部 `fallback_local`（仅 Windows；Linux 返回 None，`voice/mimo_tts_provider.py:320-322`）→ 最终无语音。
5. **语音是附加能力**：`orchestrator` 已捕获合成异常，文本回复照常下发（`orchestrator/optimized_orchestrator.py:2078-2093`）；所以最终降级是「只有文字，没有语音」，不是「消息失败」。
6. **MiMo 失败不自动回退 Breeze**（`routing.mimo-tts.fallback=[]`），避免一次 MiMo 故障把所有流量切到付费 Breeze，产生无声成本。若用户选择允许，改配置即可（Q12）。

**可观测性（复用 AGENTS v1.55 的 `quality_degraded` 日志惯例）**：
- 结构化日志：
  ```text
  tts_quality_degraded engine=breeze-tts fallback=mimo-tts reason=concurrency status=429 latency_ms=812 text_chars=73 voice_ref=sha256:...
  ```
- 不落用户原文、不落完整 voice_id（用 hash/后四位）；`text_chars` 只记长度。
- `TTSManager.health_check` 增加：
  ```python
  {
    "routing": {...},
    "last_engine_used": "breeze-tts",
    "degraded": {"breeze-tts": {"until": ..., "reason": ...}},
    "counters": {"breeze-tts": {"success": 12, "fail": 2, "degraded": 2}, ...},
  }
  ```
- 告警阈值（建议，接入现有 observability）：Breeze 5 分钟失败率 >20% 或 429 >5 次 → WARNING；连续 3 次失败 → 自动冷却 60s。

### 3.9 微信发送转码链复用

**首版（托管 mp3）无需改微信侧**：

```
BreezeTTSProvider.synthesize → SynthesizedAudio(data, fmt="mp3")
  → voice_result_payload()                     # voice/audio_result.py:62-66
  → result["voice"] = {data, format:"mp3", mime:"audio/mpeg"}
  → wechat_connector: coerce_voice_payload()   # voice/audio_result.py:69-79
  → AudioFormatConverter.to_silk(data, "mp3")  # voice/audio_converter.py:19-26
  → 失败 to_amr(data, "mp3")                   # voice/audio_converter.py:81-85
  → send_voice(silk_or_amr, fmt="silk"|"amr")  # wechat_direct/wechat_connector.py:1189-1215
  → _send_voice_message(message_type=34, voice_item=...) # :879-900
```

**注意**：
- 现有 `SynthesizedAudio` 的 MIME 映射只有 `mp3`/`wav`（`voice/audio_result.py:16-19`）。Breeze 托管默认 mp3，不需要扩展；若未来自托管官方 API 输出 **24kHz s16le PCM**，必须先在 provider 内封装成 WAV（或扩展 `SynthesizedAudio` 支持 `pcm` 并补 MIME），不能直接把 PCM 当 mp3。
- 本机 `AudioFormatConverter.health_check()` 实测 `pilk=False`（《测绘》§1.8），微信链会走 AMR 兜底；生产是否装 `pilk` 未核实（《测绘》§6.2）。Breeze 不改变这个依赖，B0 批次需要把「生产 SILK/AMR 可用性」作为上线前检查项。
- `voice_duration_ms` 目前按 `len(reply)*180` 估算（`orchestrator/optimized_orchestrator.py:2104`），不是真实音频时长。Breeze 音频实际时长可由 ffprobe 得到；首版沿用估算（不改契约），P2 若要做准确时长，给 `SynthesizedAudio` 增加可选 `duration_ms`（会改 dataclass 与序列化，需单独评审）。

## 6. 排歧问题（供用户逐条拍板）

> 统一编号与汇总索引一致；每项给选项与代价，不替用户做产品/商务决定。

- **Q0 是否引入 BreezeTTS2 / 是否修订 AGENTS L6？**（前置裁决；本仓 AGENTS:222 仍为「MiMo 唯一引擎」，LOG 末尾 2026-10-22 无本轮新裁决记录）
  - **A. 确认引入，作为 MiMo 默认之外的按角色 opt-in 引擎（推荐，若用户确有此意）**：保留 MiMo 默认，Breeze 仅灰度；需同步修订 AGENTS L6 与 `voice/__init__.py`/`tts_manager.py` 的「唯一引擎」措辞。
  - **B. 暂不引入，仅保留本文作技术预研**：零风险；代价是本次调研不进入实施。
  - **C. 直接替换 MiMo**：不推荐；成本、合规、供应商稳定性风险全量暴露（见 Q8-B）。
- **Q7 部署形态**
  - **A. 托管 API（推荐）**：零新增硬件、付费计划输出可商用；代价是 $60/1M 汉字、跨境合规、中国网络延迟未测。
  - **B. 自托管 GPU + 商业许可**：数据不出境、延迟可控；代价是 12–24GB NVIDIA GPU 机器 + BreezeBlue 商业许可 + 运维。
  - **C. 仅开发机试听**：最低成本；但不满足生产引入目标，只做质量评估。
- **Q8 Breeze 的角色定位**
  - **A. MiMo 默认 + Breeze 按角色 opt-in（推荐）**：风险/成本可控；代价是双引擎配置与测试面。
  - **B. Breeze 默认替换 MiMo**：质量可能提升；代价是成本、合规、供应商稳定性风险全量暴露。
  - **C. 仅 1 个角色灰度 1 周**：最保守；代价是收益验证慢。
- **Q9 音色策略**
  - **A. 42 角色固定设计音色（推荐首版）**：Creator 50 slots 可覆盖；代价是每角色需人工设计/验收。
  - **B. 每用户克隆自己的音色**：个性化最强；voice slots 随用户数爆炸，成本/隐私/同意流程重。
  - **C. 混合：平台固定音色 + 少量高价值用户克隆**：折中；需要权限/计费/审核体系，二期再做。
- **Q10 商用范围与许可**
  - **A. 仅 C 端免费/非商用**：自托管权重仍受非商用条款；需法务确认「免费」是否构成 commercial purpose。
  - **B. B 端商业化**：必须购买 BreezeBlue 商业许可（自托管）或维持托管付费订阅（API 输出）。
  - **C. 先 POC 不商用（推荐短期）**：只做质量/延迟/成本验证，不做商用承诺。
- **Q11 是否要求真流式（句级 TTS）**
  - **A. 首版整段合成（推荐）**：现有 orchestrator 就是 `reply[:200]` 整段（`orchestrator/optimized_orchestrator.py:2064,2078`）；改动最小。
  - **B. 句级流式**：体验更好；需改 orchestrator + `IncrementalReplyGuard` 句界 + 音频分段下发，属二期。
- **Q12 MiMo 失败时是否自动回退到付费 Breeze？**
  - **A. 不允许（推荐）**：`routing.mimo-tts.fallback=[]`；避免 MiMo 故障导致 Breeze 账单无声放大。
  - **B. 允许**：可用性优先；需设置每日字符预算/告警，否则成本不可控。
- **Q13 跨境数据合规**
  - **A. 允许**：需法务书面确认 + 用户同意 + 隐私政策更新 + 数据最小化。
  - **B. 不允许（在法务结论前按此执行）**：托管 API 出局，只能自托管 + 商业许可。
  - **C. 仅发送文本、不发送参考音频**：降低敏感度，但文本仍跨境，且克隆功能不可用。

## 7. 风险与回滚矩阵

| 风险 | 触发 | 影响 | 缓解 | 回滚 |
|---|---|---|---|---|
| Breeze 429/503 | 并发超套餐/容量不足（4 worker 下进程内信号量会把账号级并发放大 4 倍） | 语音失败或延迟 | `account_max_concurrency` 派生每进程值；套餐 < worker 数时用跨进程限流或降 worker；重试 1 次 + 回落 MiMo + 告警 | `breeze-tts.enabled=false` |
| 中国网络不可达/高延迟 | 跨境链路 | 首字慢/超时 | A2 实测；超时 15s；失败回落 | 关 Breeze，保留 MiMo |
| 成本失控 | 全量切 Breeze / MiMo 故障回退 Breeze | 账单上涨 | 默认 opt-in；`mimo-tts.fallback=[]`；每日字符预算告警 | 关 Breeze / 改 routing |
| 许可/合规 | 自托管商用/跨境 | 法律风险 | Q10/Q13 先裁决；托管付费计划书面确认 | 停用 Breeze；保留 MiMo |
| 跨引擎 voice_id 串用 | 回退时把 Breeze voice_id 传 MiMo | 无声/报错 | manager 回退清理 `model/voice_id`；catalog `(engine, voice_id)` | 修代码/关 Breeze |
| 多 worker 音色不一致 | catalog 进程内单例 | 某 worker 找不到 voice_id | 绑定后重启；B1 文档注明 | 重启/回滚绑定 |
| 生产无 pilk | 转码链 | 语音发不出/走 AMR | B0 前跑 `health_check`；必要时装 `voice-silk` extra | 不影响 Breeze 开关；独立修 |
| 质量不达预期 | 中文女声主观听评 | 用户不满意 | B2 先 1–2 角色盲评；AA 榜不等于中文角色音 | 解绑/关 Breeze |
