## 三、治理方案（方法论 → 落地）

### 3.1 P0 — CODE_GRAPH.md 增量重建（非从零）

依据：用户 08-28 纠正 + Aider Repo Map 思想（图谱=符号+关系+排名，须与代码同步才有意义）+ C4"文档过时比没有文档更糟"原则。

**规程（七步）**：
1. **基线锁定**：以 CODE_GRAPH.md v3.2（704 行）为基线，不推翻章节结构（架构分层/热路径/模块职责/风险表经 07-30 实测核实，仍然有效）。
2. **变更带提取**：`git log 08-01..HEAD --stat` + 工作区未提交变更，列出全部受影响文件（已知：SP-9 幽灵层三页、DemoPage/demo.ts、wechat_decrypt_source.py、clone 预览链路下线 fb04507、Firecrawl→Crawl4AI e1a4cec、clone_training/data_extractor.py 等）。
3. **实扫校准**：复跑 2026-07-30 同款探针（create_api_app 端点数、pages/api 模块 Glob、pytest 全量、vitest 全量）——端点/页面/模块数已有 08-28 实测（203/15/12），测试数待全量跑。
4. **图谱库重索引**：codebase-memory 图谱工具 0.9.0 重跑索引 → 更新 artifact.json → 消除 §1.2 三处时间戳矛盾。若 MCP 不可用，降级为 pydeps 静态依赖图 + 手动更新关键指标，并在文档头诚实标注降级路径。
5. **差异回写**：只改受影响章节（§1 指标、§4.2 路由、§4.9 前端、§13 更新记录），未变化章节不动。
6. **验证**：探针复核 + 全量测试基线绿 → 才能声明"完成"。
7. **登记**：§13 更新记录表新增一行 + history/INDEX.md 漂移登记簿结案。

### 3.2 P1 — 文档入口索引（治"混杂"，不搬文件）

依据：Diátaxis（按读者需求分类）+ sliver"修复优于重写"原则。

- 新建 `docs/README.md` 作为**唯一入口**：
  - 真源四件套声明（继承 VISION.md 已有分工，不重复定义内容）；
  - 每份文档标注 Diátaxis 象限（reference=CODE_GRAPH/CODEMAPS，explanation=VISION，decision record=DECISION_LEDGER/adr/，how-to=HANDOFF）与**生命周期**（truth=随变更同步 / derived=事后归档 / archive=只读）；
  - 明确 16 份 READING_REPORT_* 为 derived（一次性通读产物，已沉淀进真源，标注"仅供追溯"）；
  - 新文档准入规则：入 docs/ 必须声明象限与生命周期，否则不入。
- **不搬文件**（引用链会断），只加索引与标记，后续按规则自然归位。
- AGENTS.md §1.3 真值裁决一节追加一行指向该入口。

### 3.3 P2 — 立项补全（VISION.md 增补愿景板）

依据：Product Vision Board 五要素（Roman Pichler，2011 年创立的行业事实标准）。

- 在 VISION.md 增补「愿景板」一节：愿景（已有一句话定位✓）/ 关键功能（FEATURE_MAP 已有✓）/ **目标用户**（需用户口述：是个人用户自用？面向发售？）/ **用户需求**（情感陪伴的核心场景）/ **商业目标**（需用户口述）。
- AI 不代答商业目标——这是 PVB 中必须由产品所有者填写的部分，AI 只提供结构化框架与选项。
- 明确"不做清单"（Non-Goals）VISION.md 已有✓，保持。

### 3.4 P3 — 操作日志机制（治"无日志"）

依据：Cline Memory Bank 的 activeContext/progress 双文件实践（67k★ 项目官方方法论）+ Keep a Changelog 人类可读原则。

- 新建 `docs/journal.md`（单文件追加式，会话日志）：每会话一段——日期/任务/触达文件/验证证据/未验证项。结构仿 Memory Bank：activeContext（当前焦点）+ progress（里程碑）合并进一段。
- 配套纪律写入 AGENTS.md：**每个工作会话结束必须追加一条日志**（无日志=会话未闭环）。
- 两档自动化（需用户选）：
  - **A 纯约定**（零成本）：靠 AI 纪律追加，防漂移能力弱；
  - **B hook 自动化**（推荐）：利用宿主 hook 在会话结束自动追加占位条目，AI 只填内容。缺点是要配置宿主层，属环境改动。

## 四、双向论证

**正方（为什么值得做）**：
1. 痛点③④是用户亲历的接手成本，CODE_GRAPH 增量重建直接消灭"数字打架"（三处时间戳矛盾 + 4 项指标漂移已实证）；
2. 方案全部基于验证过的活跃方法论（非自创流程），可对外解释；
3. 治理是杠杆：入口索引 + 会话日志是**一次投入持续受益**的机制，不随功能迭代贬值；
4. 增量策略避免推翻 704 行已核实内容，风险和工作量都可控（P0 约 0.5~1 天）。

**反方（风险与代价）**：
1. 治理期间零功能产出——对策：P0~P3 设时间盒（合计 ≤2 天），防"文档完美主义"；
2. docs/README.md 索引本身可能沦为第五份混杂文档——对策：它不定义内容只声明归属，且被 AGENTS.md 真值裁决引用后成为强制入口；
3. 图谱库重索引依赖 codebase-memory 图谱工具 可用性（本会话未见该 MCP 工具）——对策：已备 pydeps 降级路径并诚实标注"未验证"；
4. 会话日志纯约定档依赖 AI 自觉，历史上这类纪律会漂移——对策：推荐 hook 自动化档。
