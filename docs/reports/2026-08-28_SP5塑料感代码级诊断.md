## 一、代码级根因链（按证据）

### 根因 1（主因）：角色卡原始 prompt 未经处理直出 UI

- **数据链实证**：`RolesPage.tsx:38` 直接渲染 `character.description`（仅 `truncate` 截断）；后端 `character_routes.py:197 _list_all_characters()` → `normalize_character_card()` 只做格式展平，**不做内容摘要化**。
- **卡库实扫**（data/characters/，53 张）：
  - **7 张卡 description 以 `[姓名:xxx][年龄:xx][性别:xx][身份:…]` 方括号字段堆叠**（上杉绘梨衣/安夏/小安等）——这是写给 LLM 的结构化 prompt，被原样倒进卡片 UI；
  - **10 张卡 description 以「你是…」开头**（可丽希亚等，最长 12704 字符）——第二人称角色设定原文，读者视角错乱（UI 对用户说"你是公主"）；
  - **28 张卡 description 为空字符串**——渲染时走 `'暂无描述'` 兜底，卡片只剩名字+标签，空洞；
  - 仅约 8 张卡（如 sys_001 孙颖莎）description 是正常第三人称简介。
- **结论**：UI 层把"LLM prompt 字段"当"产品文案"展示，这是模板感/AI 味的第一来源。

### 根因 2：标签色彩无语义规则

- `RolesPage.tsx:8` `tagClasses = ['tag-pink','tag-blue','tag-green']`，`:31` 按 `i % 3` **轮转指派**——"青梅竹马"蓝、"异地球女友"绿，纯随机。马卡龙三色体系（index.css @theme 定义完整）被当成装饰骰子，破坏 taste-skill §4.2 Color Consistency Lock（色彩须有语义一致性）。

### 根因 3：信息密度与卡片结构失衡

- 同网格内卡片高度参差（一卡 description 12704 字符 truncate 成 2 行、邻卡空描述整块留白）；`core_anchors` 有的卡 0 个有的 8 个；53 张卡无分组/无虚拟化全量铺开 4 列网格——违反 taste-skill §4.9（>5 项的集合应换 UI 组件：分组/标签页/搜索过滤，而非无限网格）。

### 根因 4：空态与数据缺失态裸奔

- `WeChatPage.tsx` 连接断开时页面主体巨幅空白，状态字段直接渲染原始值（`运行 —`、孤零零的 `0`）——违反 taste-skill §4.5（Empty States 必须精心构图并指路）。

### 根因 5（末位）：动效层未消费

- `index.css:141-165` 已有 `fade-in/pulse-glow/pulse-ring/float` 关键帧；`RolesPage` 用了 `animate-pulse`（骨架屏）但正文无入场动效。StaggerContainer/ParallaxTilt/AnimatedNumber 确于 989a237/2815135 删除——**但根因 1-4 修好之前，加动效只是给原始 prompt 直出"镀金"**。

## 二、修复方案（taste-skill Redesign-Preserve 杠杆序）

| 优先级 | 动作 | 落点 |
