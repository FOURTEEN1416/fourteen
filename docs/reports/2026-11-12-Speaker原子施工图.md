# Speaker 统一出口 · 原子施工图（2026-11-12 重规划）

> 重规划对象：工作流 `dwfrun-ff77e39d` 的第 3 步「主链/主动/手动切换与 topic_plan 清场」。
> 原第 3 步是一个巨型 hole（一条契约同时改 4 条线 + 线程表），任一子项失败会拖垮整批、
> 无法局部验收、无法并行。本图按**原子级**重拆：一个原子 = 一个 owner 文件集 + 一条可观测
> 契约 + 一个专属测试文件 + 一个确定性门禁。

## 0. 拆分原则

1. **原子 = 可独立验收的最小行为变化**，不是「一个文件」也不是「一个函数」。
2. **同文件原子串行，不同文件原子并行**；pytest 全局串行（共享 `data/` 与锁，禁止并行 pytest）。
3. 每个原子自带**回滚口径**：优先复用现有开关；没有开关的写「代码回滚」。
4. 每个原子先写专属测试，再由 `world.run` 跑 ruff + 该测试文件；失败即停在本原子，不带病进入下一个。
5. 原子之间只通过既有公共接口耦合；禁止为一个原子新建跨域抽象。

## 3. 明确不在本批（有证据的边界）

1. **不删 `topic_plan` 表**：盘点证据（`2026-11-12-Speaker施工盘点.json` threads.migrationRisks）
   显示 `agent_threads` 不是等价替代——缺 parked/salience/anchors/recall_count/TTL，且
   thread_id 不含 character_id。直接删表会丢「按角色隔离」「parked 复提」「内容计划」三项。
   本批只做 owner 收口 + 清场补洞；删表需先给 thread 系统补齐三项能力，单列下一批。
2. **主链不迁 `runtime_plane`**：主链在连接器进程内同步发送（`publish` 闭包），
   plane 是「调度器进程 → 连接器进程」的跨 worker 投递面；把同进程直发绕进 plane 会破坏
   「已发前缀永不回滚」与 `_peer_lock` 语义，收益为负。本批只把主链拆条/回执单点化。
3. **不改 LLM 供应商、提示词主体、终端守卫本体**：本批只做出口与记账收口。

## 4. 门禁与提交

- 每原子：`ruff check <changed files>` + `pytest <专属测试文件>`，两者 exit 0 才算过。
- 每波结束：该波所有原子测试并集再跑一次（仍串行）。
- 最终：`files.glob("tests/**/test_*.py")` 排序后 NR%4 分四块，逐块 `pytest -q`；
  四块通过数相加必须等于 `--collect-only` 收集数（分块清单递归覆盖 `tests/core/`、`tests/api/`）。
- 独立复核：没参与实施的复核人读 `git diff HEAD` + 新增文件，逐原子核对契约；禁止改文件、禁止跑 pytest。
- 主控按文件 `git add` + commit；**不 push、不部署**（用户裁决「只合入不部署」）。
