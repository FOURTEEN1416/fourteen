**核心机制**

1. **一人格一目录一 SKILL.md**：YAML frontmatter 的 `name` + `description`（内嵌「X 视角」触发词）承担路由，正文按需加载，靠物理文件与命名空间做隔离。
2. **固定九段模板**把人格拆成可执行字段：身份卡 → 问题分类/研究/回答三步工作流 → 5–6 条心智模型（各带来源证据与局限性）→ 决策启发式表 → 表达 DNA（句式/高频词/口头禅/禁忌词）→ 反模式与内在张力 → 诚实边界 → 调研来源。
3. **规则层与证据层分离**：`SKILL.md` 只放可执行规则，`references/research/01–06` 六件调研文件只作写作依据、运行时不注入。
4. **组合不靠混写而靠显式编排**：DirectorAgents 给出顺序链/辩论投票/主席团三模式与风格冲突检测、场景分割、首席裁决；天涯框架强制走协调者、禁止单一人格代答。
5. **防串味只有静态手段**（触发词命名空间、第一人称身份卡、反模式/禁忌词、诚实边界），无跨人格运行时裁决；`team-orchestrator.py` 是返回占位字符串的桩，无任何 LLM 调用。

## 四、总体结论

1. **真正可立即吸收的只有两条**：CSP 的「行为蒸馏 + 跨场景二重验证」补角色卡行为规则层；dsh-speak-up 的「零 token 掷骰先于 LLM」补主动线确定性闸。两者都不需要引入外部运行时。
2. **人格蒸馏三件（awesome-ai-persona-skills / CSP / nuwa）共享同一套底层思想**：规则层与证据层分离、固定字段模板、来源可追溯。差别在 CSP 偏「单角色行为蒸馏」、nuwa 偏「真人六维采集与保真度验证」、awesome 合集偏「多角色编排与静态隔离」。本仓先取 CSP，nuwa 的评分卡留黄金集，awesome 的九段模板留角色卡字段设计。
3. **记忆/情绪类（fish-memory / feiyu-mood）与既有系统存在双真源风险**：`topic_state` 只表达对话进度，不写事实；情绪维度若要接，必须复用现有 `emotion_state`/`proactive` 账本，不另建第二套存储。
4. **DSH 插件类（bili-subagent / tts-bridge / qq-bridge）多为 TypeScript/DSH 运行时耦合**：可借「看/说分离」「硬门槛放工具层」「入站攒条」等机制，但均需 Python 重写；本批不落产品代码。
5. **清单核验教训**：`Yuuyuko-uu/awesome-dsh-plugin` 是 8★ fork 且六插件未渲染，引用前必须回上游 `awesome-dsh-plugin/awesome-dsh-plugin`（21,063★）核对，避免把 fork 当权威索引。
