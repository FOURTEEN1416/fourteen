## 1. 根因 → 改动文件 → 红转绿

### D1 安全日志面板恒空 + 越权开关

**根因（三处契约错位，逐项对照 `api/routers/safety_routes.py` + `api/state/safety_log.py`）**

| 前端旧读法 | 后端真实回执 | 后果 |
|-----------|-------------|------|
| `logRes.data?.logs` | `{"log": [...]}` | 面板**恒空** |
| `d.total_detections` / `d.today_blocked` / `d.block_rate` | `get_stats()` 返回 `total_flagged` / `recent_flagged` / `by_category` / `recent` | 三项**恒 0 / —** |
| 条目 `log.content_snippet.slice(0,16)` | 条目为 `{timestamp, category, direction, text_length, text_hash}` | 渲染期**抛错**（`content_snippet` 不存在） |
| 开关对所有人渲染 | `POST /api/safety/config` = `require_role("admin")` | 普通用户点了**必 403** |

**改动**
- `frontend/src/types/api.ts`：`SafetyLogEntry` 由陈旧的 `{timestamp:string, category, message, confidence}` 改为**真实契约** `{timestamp:number(Unix 秒), category, direction:'input'|'output', text_length, text_hash, user_id?}`（全仓唯一 owner，`SettingsSecurity` 不再重复声明局部同名类型）。
- `frontend/src/pages/SettingsSecurity.tsx`：读 `log`；统计改用真实字段；`category`→中文标签映射（未收录类别原样显示，不编造）；`direction`→输入/输出；时间戳按 Unix 秒格式化（兼容毫秒 / ISO）；**admin-only 开关按 `user.role` 隐藏**；空态 `暂无安全事件`；错误态 `无法加载安全数据`+`重试`；开关按 `status === 'ok'` 判业务成功，`not_available` 给 `warning` 且**不翻转**。

### D2 角色设置深链失效

**根因**：`RoleSettings.tsx` 用 `useState('basic')` 且**完全不消费**路由 `:tab` ⇒ 任何刷新/深链必落基础页。
**改动**：`activeTab` 以 URL 为唯一真源（`:tab` 合法值直取，非法/缺省回退 `basic`）；点击 tab 用 `useNavigate` 写回 URL（基于当前 `pathname` 追加/替换末段，兼容 `/roles/:id/settings` 与 `/users/:u/roles/:id/settings` 两种前缀）。
**注**：路由 `:tab` 早已存在（`App.tsx:144`），**无需改路由**。

### D3 私人查询无账号维度 + 退出不清缓存

**改动（本窗部分）**
- `frontend/src/api/queryClient.ts`：新增 `clearAccountScopedCache()`（`queryClient.clear()`，幂等、空缓存不抛错）。
- `frontend/src/hooks/useAuth.ts`：`logout()` 后清；`applyTokenResponse()` 在 `user.id` **变化**时清（**同账号重复登录不清**，避免无谓闪烁）。
- `frontend/src/api/client.ts`：401 刷新失败（**被动登出**）路径同样清。

**并发说明（重要）**：queryKey 的**账号前缀维度**由并行窗 **W1** 在 `frontend/src/hooks/useQueries.ts` 实施（该文件本窗**未触碰**，其注释明确引用本窗的 `clearAccountScopedCache` 作为兜底）。本窗负责「登出/切换清缓存」，W1 负责「键维度主防线」，二者互补。

### D4 主动控制面板作用域错误

**根因**：角色页 `MessageTab` 直接请求**全局**主动接口并渲染**全局广播**发送按钮（「立即发送一条主动消息」），可跨角色/跨会话误投。
**改动（`frontend/src/components/admin/RoleSettingsTabs.tsx`）**
- **非 admin**：只渲染「主动消息由全局引擎统一调度…」说明，**不请求**全局接口（旧实现普通用户打开角色页即打 admin-only 接口，403 被静默吞掉后渲染默认假表单）。
- **admin**：新增**全局作用域横幅**（明示参数作用于全部角色，非本角色专属）；配置读取失败（503）→ **显式错误态 + 重试**，不渲染默认假表单。
- **移除全局广播发送按钮**；保留**只读**的「最近主动消息」记录。
- 顺带按权限隐藏另两处 admin-only 动作：**重要日期**（`PUT /characters/{id}/important-dates` = admin-only）、**知识库定期采集开关**（`POST /api/knowledge/collect-config` = admin-only）。
- `frontend/src/api/system.ts`：`proactiveSend()` 补 `sessionKey` 参数（对齐后端「目标显式优先；多路会话必须显式指定 `session_key`，否则 **400 拒猜**」）。

## 4. 未验证风险与边界（诚实登记）

1. **旅程逐步覆盖不全**：任务书验收列出的「编辑人设 → 上传知识 → 对话消费 → 改音色试听与发送 → 建/改/取消提醒 → 暂停与恢复 → 删除并查看结果」**未在本窗 E2E 中逐步驱动**。
   原因：①「对话消费」需真实模型凭证，本窗**禁读真实 `.env`/凭证**；②「音色试听/提醒投递」依赖外部服务（MiMo / 微信通道）。本窗 E2E 覆盖的是与 W11 声明面直接相关的路径（上表 11 条）+ 「创建并归属角色」。
   **结论：本窗未取得「两账号全旅程逐步通过」的证据**，仅有上述 11 条真实 API 浏览器证据。
2. **控制台无登出入口**（产品缺口，**D 类登记，不自决**）：全仓 UI 只有协议门的「不同意并退出登录」会调用 `logout()`；已登录用户在控制台**无法主动登出**，因此「A 登出 → B 登录」在真实用户路径上**不可达**。本窗以「真实 `logout()` 代码路径」+「会话失效路径」两种方式验证，**未新增登出入口**。
3. **安全开关真实写入未在浏览器执行**：`POST /api/safety/config` 会改写仓库 `config/system.yaml`，浏览器层只用故障注入验证判定逻辑；真实写入路径由 W6 窗单测覆盖。
4. **账号切换「无旧数据闪现」的机制面**：键维度由 **W1** 窗实施（`useQueries.ts`），清缓存由本窗实施；二者在合并树上一并 `tsc` 0 错 / vitest 全绿，但**未做「迟到旧账号响应写进新账号键」的浏览器级竞态复现**。
5. **E2E 依赖本机系统 Chrome**（`channel: 'chrome'`）：本机 `ms-playwright` 仅装到 `chromium-1223`，与 Playwright 1.61.1 要求的 `chromium-1228` 不匹配，故未下载新浏览器。
6. **后端分块结果不可用作本窗基线**（§2.4 污染说明）。
