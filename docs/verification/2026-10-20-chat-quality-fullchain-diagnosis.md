## 2. 根因与代码锚点

### R1 模式边界泄漏（小说模式误入）

- `shisi/core/models/character_aggregate.py:194` 无条件注入 `# 对话示例（仅示范语气与格式）`，`_format_dialogue_examples()` 在 `:224` 原样返回 `mes_example` 的 2000 字，**不区分模式**。生产 42 张卡中 37 张 `mes_example` 含括号动作（这是小说模式的合法写法），被整段喂进沉浸式 prompt。
- 同一文件 `:186` 无条件注入 `first_mes`；角色卡 `creator_notes` 也可能包含动作描写。三者共同构成“小说格式 few-shot”。
- 注入文案写的是“示范语气与格式”，而 `utils/reply_mode.py:57` 的沉浸式指令明确“严禁括号动作/神态/环境/心理描写”。**同一份 system prompt 内自相矛盾**，模型随机挑一个。
- `orchestrator/optimized_orchestrator.py:1232` 把模式指令放在 system prompt 末尾，冲突时**理论上**应优先；但 few-shot 的格式示范是“看例子学”的强信号，文字禁令压不住。agnes 不可用时降级到更弱模型，禁令更容易失守。
- `utils/reply_mode.py` 的读取/写入是**全局单例**（`data/scheduler_config.json` 一个键），前端却放在角色页的消息 tab。一个开关影响所有用户/角色，模式必然互相污染。

### R2 过度指令的对话策略（复述 / 虚构反问 / 客服腔）

- `utils/reply_mode.py:58`：“需要时**反问一句**把话题往前推”；`:60`：“或**自然追问一句**……层层深入”。
- `utils/prompt_sanitize.py:231`：“话题说下去（补充想法/经历/**自然追问**）”；`:362`：“或就这件事**自然追问一句**”；`:364`：“**连续追问/补充比抛新话题更像真人**”。
- 这些指令与“不要编造对方处境”并存，模型在没有可接的具体内容时，最省力的合规动作就是抛一个泛问句——“你呢，有没有什么特别想吃的？”正是这条策略的直接产物。
- “复述”同源：prompt 要求“接住对方刚说的细节”，弱模型把它实现成复读原句；`ROLE_CLARITY_RULE`（`utils/prompt_sanitize.py:189`）只说明角色归属，没有禁止逐字复述。
- 元解释“我想确认一下你是不是真的记得，有时候我会忘记自己说过的话”不是角色卡内容，也不是用户说的；它是模型在“记忆/画像/确认”语义附近自由生成的**元话语**，当前没有任何出站检查能拦住它。

### R3 没有对话状态与语义终审（话题意识失败）

- `utils/prompt_sanitize.py:219 extract_current_topics` 是关键词袋：任取 2–6 字 token，最多 3 个。实测问候句返回 `['的话', '哈喽']`，再把它们写进 `persona_service.py:144` 的 `## 当前话题（请沿着聊下去）`。这既不是话题，也没有说话人、时间、未完成事项。
- `utils/prompt_sanitize.py:580 terminal_reply_guard` 只做哨兵、系统标记、时间词、emoji 回显、称呼退化等**格式层**处理。对逐字复述、归属翻转、无由头反问、元解释、沉浸式括号动作**全部放行**（已用生产原句实测）。
- 因此问题回复能原样落库并送达；后续历史又把它们当正常 assistant 轮次喂回模型，形成自我强化。

### R4 静默降级放大器（质量悬崖）

- `llm_provider/openai_compatible_provider.py:351` 在 HTTP 200 后直接 `content = data["choices"][0]["message"]["content"]`；`:361` 先 `entry.mark_success()` 再 `content.strip()`。若上游返回 `content: null` 或只有 `reasoning_content`，`strip()` 抛 `AttributeError`，随即被 `:363` 的宽 `except` 捕获。
- 捕获后 `:367` 调 `_try_fallback`，同 provider 换模型；`:430-458` 的 fallback 循环对每个异常**只 `mark_failed()`，不记录异常类型/响应体**。生产日志只看到 agnes 200 后立刻 cooldown，真正的失败原因（空内容/字段缺失）没有落日志。
- 熔断阈值 `_BREAKER_THRESHOLD = 1`、冷却 300 秒（`llm_provider/multi_provider_gateway.py:294`）：一次坏响应就让主模型退场 5 分钟。17:52:29、17:53:39 两条问题回复都发生在这个降级窗口内，由更弱的后备模型生成。
- 结论：即使 prompt 改对，**静默换模型仍会把质量打回原形**；可观测性与降级策略必须同批修。

### R5 仓库认知债（盲人摸象的结构原因）

- 当前实测：710 个 Python 文件 / 179,613 行；`tests/` 235 个测试文件；`create_api_app` 实扫 **229 APIRoute / 194 唯一路径 / 233 routes**。
- `CODE_GRAPH.md` 版本头仍是 v3.8.32（2026-10-17，3554 收集），落后于 AGENTS v1.53（2026-10-19，3584 收集）；端点口径也未随最近批次回扫。文档是人工快照，无法阻止漂移。
- 已安装 AOCI（见第 4 节），它把“每文件一条 F/R/A/S 语义索引”放进 Git，成为可增量维护的结构真源；本次仅完成初始化和基线扫描，索引条目需 MCP 重连后由模型分批写入。

## 5. 执行计划（按批独立可回滚）

### 批次 A：模式契约（P0，阻断）

1. `reply_mode` 从全局单例改为**角色级 + 用户级覆盖**，保留全局默认；前端开关移出角色页或明确标注作用域。
2. 在 `CharacterAggregate.build_system_prompt` 前加模式过滤：沉浸式下对 `mes_example`/`first_mes` **剥离括号动作段**（保留纯对话行），小说模式原样保留；`creator_notes` 中的格式要求与模式冲突时以模式为准。
3. 去掉 `# 对话示例` 文案里的“示范格式”，改为“仅示范说话口吻；格式以【回复模式】为准”。
4. 验收：沉浸式 prompt 中 0 个括号动作样本；小说模式样本不丢；生产 62105bca 卡的示例在两种模式下行为正确。

### 批次 B：对话策略减负（P0）

1. 删除/改写 `reply_mode.py:58,60` 与 `prompt_sanitize.py:231,362,364` 的“反问/追问/连续追问”激励。
2. 新增“先回应，再决定是否提问”的单一规则：只有用户刚说的事里有**可指认的未完成点**时才问；问句必须能回指到用户上一句的具体词。
3. 新增“禁止逐字复述用户”“禁止元解释自己的记忆/确认意图”两条硬规则。
4. 验收：生产 2869/2873/2875 三句在离线重放中不再出现；20 条正常对话不被误伤。

### 批次 C：语义终审（P0，最后防线）

在 `terminal_reply_guard` 增加四类确定性处理，全部只处理**可判定**形态并落日志：

1. 逐字复述：回复首句与用户上一条归一化后完全相同 → 剥除首句。
2. 归属翻转/元解释：命中“我想确认一下你是不是真的记得 / 有时候我会忘记自己说过的话 / 你是说刚刚我说的” → 剥除该句。
3. 无由头泛问：命中“你呢，有没有什么特别想…的？”且上一轮用户没有对应问句 → 剥除。
4. 沉浸式括号动作：`reply_mode=immersive` 时剥除成对括号动作段；小说模式不动。

每条命中写 `reply_guard_hit` 结构化日志，便于统计复发率；不做“改写成另一句”的生成式修补。

### 批次 D：Provider 可观测与降级质量（P0）

1. 显式处理 `content is None/空`、缺 `choices`、只有 `reasoning_content` 三种响应；失败原因写 `llm_empty_content` / `llm_bad_shape`，附响应前 200 字。
2. `_try_fallback` 记录每个候选的异常类型与状态码，不再裸 `except`。
3. 降级时向主链发 `quality_degraded` 信号，终审记录本次回复由后备模型生成；对情绪主链是否允许静默降级给出显式策略（建议：允许保可用，但必须可见 + 记录）。
4. 验收：构造 200+空 content 的假上游，日志可定位；不再出现“200 后无原因 cooldown”。

### 批次 E：话题状态（P1）

1. 用“最近 N 轮对话锚点”替代关键词袋：记录最后一条用户消息的具体对象/事件/未完成点，24h 窗，无时间戳 fail-open。
2. 删除 `## 当前话题（请沿着聊下去）` 的关键词列表；改为“上一轮用户在说 X，先接住 X”。
3. 验收：`['的话','哈喽']` 类噪声不再出现；跨 24h 旧话题不教唆。

### 批次 F：黄金集回归（P1）

- 固定 20 条坏例（本轮 5 条 + 历史 15 条）+ 20 条好例，覆盖 agnes/zhipu 两模型；每次 prompt/guard 改动跑一遍，作为发布门。
- 指标：复述率、元解释率、无由头问句率、沉浸式括号率、话题接续率。

### 批次 B · 对话策略减负（R2）

### 批次 C · 语义终审（R3）

`utils/prompt_sanitize.py::terminal_reply_guard` 新增 `reply_mode` 参数与四道确定性守卫，顺序在错误哨兵/系统标记之后、emoji 回显/称呼之前：

1. `_strip_immersive_stage_directions`：仅 `reply_mode=immersive` 时剥括号/星号动作段；小说模式与缺省（主动/提醒链）不动。
2. `_strip_verbatim_echo`：回复首行与用户上一条归一化后等值（≥5 字）→ 删首行。
3. `_strip_meta_memory_talk`：句级删除「我想确认一下你是不是/是否…」「你是不是真的记得」「忘记自己说过的话」「记性不好」与零信息问卷（「有没有什么特别的事情想和我分享」）。
4. `_strip_ungrounded_reciprocal`：**仅在用户本轮有发言且未提问时**，截掉「你呢，…？」及其后文；主动链 `user_msg=""` 不启用（「我这边下雨了，你呢带伞没」是合法主动开场）。

命中写 `reply_guard_hit rule=… before_len=… after_len=…` 结构化日志（不落用户原文/回复原文）。`orchestrator/optimized_orchestrator.py::_finalize_reply` 接入 `read_reply_mode()`；主动/提醒链保持缺省参数，行为不变。

说明：四类是「可判定形态」的确定性剥除，不做生成式改写；剥空后由既有 `empty_reply` 兜底链路处理。

### 批次 D · Provider 可观测（R4）

`llm_provider/openai_compatible_provider.py`：

- 非流式主请求与 fallback 循环均在 `mark_success()` **之前**校验 `choices[0].message.content` 为非空字符串；None/空白/缺 choices/仅 reasoning_content 一律抛 `RuntimeError`，不让空响应污染健康统计。
- 主请求失败日志补 `type(e)`、异常消息与响应体前 300 字（`body=…`）；fallback 每个候选失败都落 WARNING（模型名 + 异常类型 + 消息），不再裸 `except`。
- 空内容/坏结构现在可从日志直接定位；熔断（阈值 1 / 冷却 300s）行为本身未改，仍属二期策略项。

### 批次 E · 话题噪声（R3 配套）

# 第二轮（同日）：为什么「改了那么多次还复发」

> 触发：用户复报同一批问题并追问「已经更新过那么多次了，还是这样？？问题还越改越大？」。
> 结论：**上一轮的五条根因都成立，但都不是复发机制本身**。真正的放大器是「首次选模型就被
> 静默换掉」，加上三条上一轮没覆盖的注入通道。v1.54 当时**从未部署**（服务器停在 `1fd0906`），
> 所以用户看到的现象里，有一部分根本不是新代码的行为。

## 8. 决定性取证

### 8.1 报障回复不是首选模型写的

生产 `data/app.log`（2026-10-20 17:45–17:53）与 `chat_history` 2846–2875 对齐：

| 时刻 | 事件 |
|---|---|
| 17:51:31 | `POST apihub.agnes-ai.com` → **HTTP 200**（请求成功到达） |
| 17:51:32 | `agnes 连续失败 1 次，熔断 300s`；`agnes failed: 模型请求失败` |
| 17:51:36 | `POST open.bigmodel.cn` 成功 → 回复落库 |
| 17:52:20 | 同一分钟 agnes 连续失败 2 次 |
| 17:52:24 | 智谱接管 → **17:52:29 写入 2873（逐字复述）** |
| 17:53:37 | 智谱 → **17:53:40 写入 2875（括号+归属翻转+元解释）** |

当日统计：`agnes` 24 次调用 **15 次失败 / 10 次熔断**。也就是说，用户报障的那几条回复，
**全部是降级模型 `glm-4.5-flash` 写的**，不是被寄予厚望的 `agnes-3.0-flash`。

### 8.2 为什么首选模型会被判死：延迟实测

用生产同形状 prompt（system ~5.9k 字 + 19 条历史 + `max_tokens` 512~2048）直连 agnes 实测：

```
1.11s / 2.36s / 3.39s / 10.47s / 10.94s / 24.63s / 37.40s / 51.69s
```

配置里的 `request_timeout = 15`。**24.63 / 37.40 / 51.69 这三条都是健康响应**，
全部被 15s 判死 → 触发 `_BREAKER_THRESHOLD = 1`（一次失败即熔断）→ 冷却 `300s`。
于是一条正常但慢的回复，会把整段对话推到弱模型那边五分钟。

这是「越改越大」的机制：**每一批 prompt 修复都让 system prompt 变长**（禁令、锚点、
格式优先级、话题块），prompt 越长 agnes 越慢，越容易被 15s 误杀，越多流量落到弱模型，
于是越改越像客服腔。修复 prompt 的努力，被降级路径系统性地抵消。

### 8.3 三条上一轮没覆盖的通道

| # | 通道 | 证据 | 影响 |
|---|---|---|---|
| 1 | **知识库里的 mes_example** | 生产 `prompt_slots`（event 15690）`knowledge_snippets[0]` = `用户：今天加班到现在才走…（想了想）周五我来给你做饭` | `mes_example` 同时被索引进知识库，上一轮只剥了「对话示例」段，RAG 这条并行通道照旧把括号动作 few-shot 进沉浸式 |
| 2 | **归属翻转** | 2875「哦，你是说刚刚**我说的**“点完名就吃”吗？」——那句是**用户**说的 | 上一轮只拦了逐字复述与元解释；把用户台词记到自己名下 = 编造共同经历，且同时篡改归属 |
| 3 | **裸「你呢」** | 2871「刚吃完饭 / 你呢 / 没课的时候别又错过吃饭时间了」 | 上一轮的正则要求「你呢」后带 `？`，这一形态漏网 1/1 |

### 8.4 自我强化回路（这才是「还犯」）

出站守卫只保护**本次发送**。被判死的回复已经作为 `assistant` 行落库，下一轮
`sanitize_llm_history` 把它当「我自己说过的话」原样喂回模型 few-shot。
所以即使当轮拦住了，下一轮模型照样从历史里学会这种句式 —— 这就是
「明明修了、过几天又出现」的结构原因。

### 8.5 话题意识：关键词袋不是话题

`extract_current_topics` 生产实测输出 `['的话', '哈喽']`。它从整段 blob（含 assistant 行）
随机切 2~6 字 token，既不成句，也没有说话人。注入文案是「## 当前话题（请沿着聊下去）」，
模型拿到的只有噪声，于是每轮另起炉灶 —— 用户反复报「没有话题意识」的直接原因。

### 9.1 质量悬崖（R1，本轮最关键）

  一样，沉浸式下先 `strip_stage_directions`（生产 `knowledge_snippets` 实测带括号）。

### 9.3 出站守卫补漏（R3）

- `_RECIPROCAL_QUESTION_RE` 增加「裸『你呢』独占一行」形态，需 `re.MULTILINE`；
  只删该行、不吞后续正常内容。
- 反向保护：`你呢，别太累了` 是陈述句不是提问，不得误删（首版被既有用例
  `test_non_question_ni_ne_kept` 当场抓住，改为精确整行匹配）。

### 9.4 历史回灌净化（R4）

`_prepare_context` 在历史注入前就地净化 assistant 行：沉浸式剥括号动作、
删元记忆解释、删归属翻转；整行剥空则丢弃并计数 `历史回灌净化：丢弃 N 条`。
**只改内存副本，不动库**（原文保留供排障）。

### 9.5 话题锚点替换关键词袋（R5）

新增 `_extract_user_anchor_sentences`：只取 **user 行**的**完整短句**，过滤纯寒暄
（`哈喽/嗯/好的`）与空应答（`暂时没有/不知道/随便`），沿用 24h 时间窗。
注入文案改为「## 对方最近在说（这些是**对方**的原话，不是你说的；先接住具体内容）」。
实测：`['今天下午没课', '我在宿舍待着', '等下点完名再去吃吧']`。

### 9.6 与爱语的对照（回答「为什么逆向对照了还达不到」）

`aiyu_prompts_full.json` 43 条全量检索：`反问/追问/话题/复述/确认一下/你呢` **全部 0 次**。
爱语的提示词集中在**思维链、记忆指令（`<add>`/`<search>`）、语音与表情格式**，不含任何
「怎么聊天」的策略指令。差距不在规则不够聪明，而在我们把「像真人」拆成了多条互相竞争的
硬指令 —— 弱模型在规则压力下最省力的合规动作就是抛模板句。**继续加规则会继续恶化**；
本轮方向是减指令 + 加状态 + 加确定性终审。

## 11. 仍未解决（诚实清单）

1. **agnes 本身的不稳定**：实测延迟跨 1.1~51.7s，即使 40s 阈值仍有长尾会走到降级。
