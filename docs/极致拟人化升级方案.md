## 二、P0级升级方案

### 2.1 Token预算管理器

#### 2.1.1 问题分析
当前项目**没有全局token预算管理**。`EnhancedPromptEngine`的6层prompt + 记忆层 + 对话历史 + RAG结果拼在一起后，总token数不可控。当使用小context模型（如智谱GLM-4-Flash 128K）时不会出问题，但切换到大模型或本地部署模型时可能超出context limit。

#### 2.1.2 借鉴来源：SillyTavern `ChatCompletion` 类

**源码位置**：`public/scripts/openai.js` 第3822行

**核心设计模式**：reserve/free/canAfford三操作预算管理

```javascript
// SillyTavern核心模式（JavaScript，需转译为Python）
class ChatCompletion {
    tokenBudget  // 总预算 = max_context - max_tokens_for_generation
    
    add(collection)        // 添加内容，扣减预算
    reserveBudget(msg)     // 预留预算（不实际添加）
    freeBudget(msg)        // 释放预留
    canAfford(msg)         // 检查是否负担得起
}
```

**关键策略**：
- 从最新消息向最早消息**反向填充**chat history
- 系统prompt优先级高于chat history
- `pin`机制确保关键prompt始终保留

#### 2.1.3 具体改造方案

**新建文件**：`my_character/token_budget.py`

```python
"""
Token预算管理器
借鉴SillyTavern ChatCompletion的reserve/free/canAfford模式
"""
import tiktoken
from dataclasses import dataclass, field
from typing import List, Optional, Tuple
from enum import Enum

class PromptPriority(Enum):
    CRITICAL = 0   # 不可裁剪：角色核心设定、约束层
    HIGH = 1       # 高优先级：情感层、记忆层
    MEDIUM = 2     # 中优先级：风格层、认知聚焦层
    LOW = 3        # 低优先级：few-shot示例、RAG结果
    FLEXIBLE = 4   # 可裁剪：对话历史（从最早开始裁剪）

@dataclass
class PromptSegment:
    """一个prompt片段"""
    name: str                    # 标识符，如 "base_layer", "emotion_layer"
    content: str                 # 文本内容
    priority: PromptPriority     # 优先级
    pinned: bool = False         # 是否固定（不可裁剪）
    min_chars: int = 0           # 最小保留字符数（裁剪时的下限）
    tokens: int = 0              # 缓存的token数

class TokenBudgetManager:
    """
    Token预算管理器
    核心机制：为每个prompt片段分配token预算，超出时按优先级裁剪
    """
    def __init__(self, max_context_tokens: int, max_output_tokens: int = 2048,
                 encoding_name: str = "cl100k_base"):
        self.max_context = max_context_tokens
        self.max_output = max_output_tokens
        self.total_budget = max_context_tokens - max_output_tokens
        self.encoding = tiktoken.get_encoding(encoding_name)
        self._reserved: int = 0
        self._segments: List[PromptSegment] = []
    
    def count_tokens(self, text: str) -> int:
        return len(self.encoding.encode(text))
    
    def remaining_budget(self) -> int:
        used = sum(s.tokens for s in self._segments) + self._reserved
        return max(0, self.total_budget - used)
    
    def can_afford(self, content: str) -> bool:
        return self.count_tokens(content) <= self.remaining_budget()
    
    def add(self, name: str, content: str, priority: PromptPriority,
            pinned: bool = False, min_chars: int = 0) -> bool:
        """添加prompt片段，返回是否成功"""
        tokens = self.count_tokens(content)
        segment = PromptSegment(name=name, content=content,
                                priority=priority, pinned=pinned,
                                min_chars=min_chars, tokens=tokens)
        if tokens <= self.remaining_budget() or pinned:
            self._segments.append(segment)
            return True
        return False
    
    def allocate(self) -> Tuple[str, dict]:
        """
        分配预算并返回最终prompt
        策略：
        1. pinned片段始终保留
        2. 按优先级排序非pinned片段
        3. 从低优先级开始裁剪，直到预算内
        4. 对话历史从最早开始裁剪
        """
        pinned = [s for s in self._segments if s.pinned]
        flexible = sorted(
            [s for s in self._segments if not s.pinned],
            key=lambda s: s.priority.value,
            reverse=True  # 高优先级先保留
        )
        
        budget_used = sum(s.tokens for s in pinned)
        result_segments = list(pinned)
        stats = {}
        
        for seg in flexible:
            if budget_used + seg.tokens <= self.total_budget:
                result_segments.append(seg)
                budget_used += seg.tokens
                stats[seg.name] = "full"
            elif seg.min_chars > 0:
                # 裁剪到min_chars
                truncated = self._truncate_to_budget(seg, self.total_budget - budget_used)
                if truncated:
                    result_segments.append(truncated)
                    budget_used += truncated.tokens
                    stats[seg.name] = "truncated"
                else:
                    stats[seg.name] = "dropped"
            else:
                stats[seg.name] = "dropped"
        
        # 按原始优先级排序输出
        result_segments.sort(key=lambda s: s.priority.value)
        final_prompt = "\n\n".join(s.content for s in result_segments)
        return final_prompt, stats
    
    def _truncate_to_budget(self, seg: PromptSegment, budget: int) -> Optional[PromptSegment]:
        """将片段裁剪到指定预算"""
        # 按行裁剪，保留最后min_chars对应的行数
        lines = seg.content.split('\n')
        truncated_lines = []
        tokens_used = 0
        for line in reversed(lines):
            line_tokens = self.count_tokens(line + '\n')
            if tokens_used + line_tokens > budget:
                break
            truncated_lines.insert(0, line)
            tokens_used += line_tokens
        if truncated_lines:
            new_content = '\n'.join(truncated_lines)
            return PromptSegment(
                name=seg.name, content=new_content,
                priority=seg.priority, pinned=seg.pinned,
                min_chars=seg.min_chars, tokens=tokens_used
            )
        return None
```

### 2.2 认知聚焦层（Cognitive Focus Layer）

#### 2.2.1 问题分析
当前项目的prompt架构是"直接生成"模式——模型收到用户消息后直接输出回复。没有"先思考再回复"的认知过程。Character-R1论文证明，显式的认知聚焦可以显著降低OOC（出戏）率。

#### 2.2.2 借鉴来源：Character-R1论文

**核心机制**：模型在输出最终回复前，先在`<thinking>`标签中进行认知推理，声明当前的关注维度（Focus）和具体描述（Focus Attribute）。

**10大认知维度**：Knowledge, Style, Worldview, Emotion, Empathetic, Engagement, Safety等

**关键洞察**：不需要训练模型，通过prompt工程即可实现类似效果。在system prompt中要求模型"先思考再回复"，思考过程不展示给用户。

#### 2.2.3 具体改造方案

**改造文件**：`my_character/enhanced_prompt_engine.py`

## 三、P1级升级方案

### 3.1 WorldInfo动态注入引擎

#### 3.1.1 问题分析
项目已有WorldInfo数据模型（`character_card/models.py`的`WorldInfoEntry`），支持keys/content/secondary_keys/selective/insertion_order等完整字段。但 `prompt_builder.py` **仅注入`constant=True`的条目**，没有基于用户消息的keys匹配动态注入。这意味着大部分WorldInfo条目永远不会被使用。

#### 3.1.2 借鉴来源：SillyTavern `world-info.js`

**源码位置**：`public/scripts/world-info.js` 第4597行 `checkWorldInfo()`

**核心算法**：
1. 维护一个扫描缓冲区（buffer），初始为用户消息 + 最近N条对话
2. 对每个WI条目，检查其keys是否匹配buffer中的文本
3. 支持三种匹配：关键词（全词/子串）、正则、constant
4. secondary_keys通过selective逻辑（AND_ANY/NOT_ALL/NOT_ANY/AND_ALL）控制二级匹配
5. 递归扫描：新激活条目的content加入buffer，继续扫描
6. Token预算控制：WI总token不超过配置比例

#### 3.1.3 具体改造方案

**改造文件**：`character_card/prompt_builder.py`

```python
# prompt_builder.py 新增动态注入方法

import re
from typing import List, Set, Optional
from dataclasses import dataclass

@dataclass
class MatchedEntry:
    """匹配到的WI条目及其匹配信息"""
    entry: 'WorldInfoEntry'
    matched_keys: List[str]
    match_score: float  # 匹配的key数量 / 总key数量

class WorldInfoScanner:
    """
    WorldInfo动态扫描引擎
    借鉴SillyTavern world-info.js的checkWorldInfo()核心逻辑
    
    改造点：将JavaScript的状态机扫描逻辑转译为Python，
    保留核心的递归扫描、selective逻辑、token预算控制
    """
    
    def __init__(self, max_budget_ratio: float = 0.15,
                 max_budget_cap: int = 2000,
                 max_recursion: int = 3,
                 min_activations: int = 2):
        self.max_budget_ratio = max_budget_ratio  # WI占总context的比例
        self.max_budget_cap = max_budget_cap        # WI最大token硬上限
        self.max_recursion = max_recursion          # 最大递归扫描次数
        self.min_activations = min_activations      # 最少激活条目数
    
    def scan(self, user_message: str, recent_messages: List[str],
             world_info_book: 'WorldInfoBook',
             max_context_tokens: int) -> str:
        """
        执行WorldInfo扫描并返回注入文本
        
        参数:
            user_message: 当前用户消息
            recent_messages: 最近N条对话消息
            world_info_book: WorldInfo条目集合
            max_context_tokens: 模型最大context token数
        
        返回:
            拼接好的WI注入文本
        """
        if not world_info_book or not world_info_book.entries:
            return ""
        
        # 1. 构建扫描缓冲区
        buffer_text = user_message + "\n" + "\n".join(recent_messages[-5:])
        
        # 2. 计算token预算
        budget = min(
            int(max_context_tokens * self.max_budget_ratio),
            self.max_budget_cap
        )
        
        # 3. 执行扫描（支持递归）
        matched = self._scan_entries(
            buffer_text, world_info_book.entries, budget, recursion=0
        )
        
        # 4. 按insertion_order降序排序
        matched.sort(key=lambda m: m.entry.insertion_order or 0, reverse=True)
        
        # 5. 拼接结果，控制token预算
        result_parts = []
        used_tokens = 0
        for m in matched:
            entry_tokens = self._estimate_tokens(m.entry.content)
            if used_tokens + entry_tokens > budget:
                break
            result_parts.append(m.entry.content)
            used_tokens += entry_tokens
        
        return "\n".join(result_parts) if result_parts else ""
    
    def _scan_entries(self, buffer_text: str, entries: List['WorldInfoEntry'],
                      budget: int, recursion: int) -> List[MatchedEntry]:
        """核心扫描逻辑"""
        if recursion > self.max_recursion:
            return []
        
        matched = []
        recurse_buffer_parts = []
        
        for entry in entries:
            if not entry.enabled:
                continue
            
            # constant条目始终匹配
            if getattr(entry, 'constant', False):
                matched.append(MatchedEntry(
                    entry=entry, matched_keys=["*constant*"], match_score=1.0
                ))
                recurse_buffer_parts.append(entry.content)
                continue
            
            # 关键词匹配
            primary_match = self._match_keys(
                buffer_text, entry.keys, 
                getattr(entry, 'case_sensitive', False),
                getattr(entry, 'match_whole_words', False)
            )
            
            if not primary_match:
                continue
            
            # secondary_keys selective逻辑
            if (getattr(entry, 'secondary_keys', None) and 
                getattr(entry, 'selective', False)):
                
                secondary_match = self._match_keys(
                    buffer_text, entry.secondary_keys,
                    getattr(entry, 'case_sensitive', False),
                    getattr(entry, 'match_whole_words', False)
                )
                
                selective_logic = getattr(entry, 'selective_logic', 0)
                # 0=AND_ANY, 1=NOT_ALL, 2=NOT_ANY, 3=AND_ALL
                if selective_logic == 1 and len(secondary_match) == len(entry.secondary_keys):
                    continue  # NOT_ALL: 所有secondary都匹配则不激活
                elif selective_logic == 2 and len(secondary_match) > 0:
                    continue  # NOT_ANY: 任何secondary匹配则不激活
                elif selective_logic == 3 and len(secondary_match) < len(entry.secondary_keys):
                    continue  # AND_ALL: 不是所有secondary都匹配则不激活
            
            matched.append(MatchedEntry(
                entry=entry,
                matched_keys=primary_match,
                match_score=len(primary_match) / max(len(entry.keys), 1)
            ))
            recurse_buffer_parts.append(entry.content)
        
        # 递归扫描：新激活条目的content加入buffer
        if recurse_buffer_parts and recursion < self.max_recursion:
            extended_buffer = buffer_text + "\n" + "\n".join(recurse_buffer_parts)
            # 只扫描尚未匹配的条目
            matched_entry_ids = {id(m.entry) for m in matched}
            remaining = [e for e in entries if id(e) not in matched_entry_ids]
            if remaining:
                recursive_matches = self._scan_entries(
                    extended_buffer, remaining, budget, recursion + 1
                )
                matched.extend(recursive_matches)
        
        return matched
    
    def _match_keys(self, text: str, keys: List[str],
                    case_sensitive: bool, whole_words: bool) -> List[str]:
        """关键词匹配"""
        if not keys:
            return []
        
        search_text = text if case_sensitive else text.lower()
        matched = []
        
        for key in keys:
            key = key.strip()
            if not key:
                continue
            
            # 正则匹配（以/开头和结尾）
            if key.startswith('/') and key.endswith('/'):
                pattern = key[1:-1]
                try:
                    if re.search(pattern, text, re.IGNORECASE if not case_sensitive else 0):
                        matched.append(key)
                except re.error:
                    continue
                continue
            
            key_search = key if case_sensitive else key.lower()
            
            if whole_words:
                # 全词匹配：使用\W作为单词边界
                pattern = r'(?<!\w)' + re.escape(key_search) + r'(?!\w)'
                if re.search(pattern, search_text):
                    matched.append(key)
            else:
                if key_search in search_text:
                    matched.append(key)
        
        return matched
    
    def _estimate_tokens(self, text: str) -> int:
        """粗略估算token数（中文约1.5字/token）"""
        return int(len(text) * 1.5)
```

### 3.2 记忆Reflection机制

#### 3.2.1 问题分析
当前记忆管线有提取（FactExtractor）和存储（SemanticMemory），但**没有从记忆中反思学习的能力**。Generative Agents证明，定期反思可以从碎片记忆中提炼高层洞察，显著提升AI的行为一致性。

#### 3.2.2 借鉴来源：Generative Agents + Letta Sleeptime

**Generative Agents的Reflection机制**：
1. 每100步触发一次反思
2. 从记忆流中检索最近的重要记忆
3. 让LLM提出3个高层问题
4. 对每个问题检索相关记忆并回答
5. 将洞察存回记忆流，标记为reflection类型

**Letta的Sleeptime机制**：
- Agent在"睡眠"时使用 `memory_rethink` 工具重新审视和重组记忆
- 不影响实时对话性能

#### 3.2.3 具体改造方案

**改造文件**：`memory/memory_pipeline.py`

```python
# memory_pipeline.py 新增方法

class MemoryReflection:
    """
    记忆反思引擎
    借鉴Generative Agents的Reflection机制 + Letta的Sleeptime模式
    
    集成位置：MemoryPipeline.daily_maintenance() 末尾
    触发条件：对话轮次累计达到阈值（如每20轮）或每日维护时
    """
    
    def __init__(self, semantic_memory, episodic_memory, llm_gateway,
                 trigger_rounds: int = 20):
        self.sm = semantic_memory
        self.em = episodic_memory
        self.llm = llm_gateway
        self.trigger_rounds = trigger_rounds
        self._round_counter = 0
    
    def should_reflect(self) -> bool:
        """检查是否应该触发反思"""
        self._round_counter += 1
        return self._round_counter >= self.trigger_rounds
    
    async def reflect(self, persona_name: str) -> Optional[List[dict]]:
        """
        执行反思
        
        步骤：
        1. 获取最近的重要事实和对话片段
        2. 让LLM提炼高层洞察
        3. 将洞察存入语义记忆（category=reflection）
        4. 重置计数器
        """
        # 1. 获取最近的记忆
        try:
            recent_facts = self.sm.get_facts(limit=30)
        except Exception:
            recent_facts = []
        
        try:
            recent_episodes = self.em.search("", top_k=5)
        except Exception:
            recent_episodes = []
        
        if not recent_facts and not recent_episodes:
            self._round_counter = 0
            return None
        
        # 2. 构建反思prompt
        facts_text = "\n".join(
            f"- {f['fact']}" if isinstance(f, dict) else f"- {f}"
            for f in recent_facts[:20]
        )
        episodes_text = "\n".join(
            f"- {ep.get('metadata', {}).get('summary', str(ep))}"
            for ep in recent_episodes[:5]
        )
        
        prompt = (
            f"你是{persona_name}。请回顾最近的记忆片段，进行自我反思。\n\n"
            f"## 已知关于用户的事实\n{facts_text}\n\n"
            f"## 最近的对话片段\n{episodes_text}\n\n"
            f"请从以下角度提炼3-5条高层洞察（每条不超过30字）：\n"
            f"1. 用户的性格特征或习惯\n"
            f"2. 用户最近的情感状态\n"
            f"3. 用户对我们的关系态度\n"
            f"4. 值得记住的重要发现\n"
            f"5. 我自己对这段关系的感觉变化\n\n"
            f"以JSON数组格式输出：[{{\"insight\": \"...\", \"category\": \"...\"}}]"
        )
        
        try:
            result = await self.llm.chat_sync(query=prompt, max_tokens=512)
            # 解析JSON
            import json
            insights = json.loads(result)
            
            # 3. 存入语义记忆
            for insight in insights:
                if isinstance(insight, dict) and "insight" in insight:
                    self.sm.add_fact(
                        fact=insight["insight"],
                        category="reflection",
                        confidence=0.7,
                        source="reflection_engine",
                    )
            
            self._round_counter = 0
            return insights
            
        except (json.JSONDecodeError, Exception) as e:
            logger.warning(f"反思执行失败: {e}")
            self._round_counter = 0
            return None
```

### 3.3 上下文智能压缩

#### 3.3.1 问题分析
当前 `ConversationSummarizer` 使用固定阈值（keep_recent=50, summary_trigger=80），超出80条时对旧消息做一次性LLM摘要。问题：
- 摘要是全量替换，没有渐进式压缩
- 只有一种压缩模式，没有降级策略
- 不感知token预算

#### 3.3.2 借鉴来源：Letta `compact.py`

**核心设计**：
- 4种压缩模式：all / sliding_window / self_compact_all / self_compact_sliding_window
- 降级链：self_compact -> sliding_window -> all
- 90% context使用率触发压缩
- 优先使用轻量模型做摘要

#### 3.3.3 具体改造方案

**改造文件**：`memory/conversation_summarizer.py`

```python
# conversation_summarizer.py 改造

class CompressionMode(Enum):
    SLIDING_WINDOW = "sliding_window"           # 保留最近N条 + 摘要旧消息
    AGGRESSIVE = "aggressive"                    # 更激进的压缩（更短摘要）
    TEMPLATE = "template"                        # 模板摘要（不调用LLM，仅统计）

class SmartCompressor:
    """
    智能上下文压缩器
    借鉴Letta compact.py的多模式压缩 + 降级链设计
    
    集成位置：替换 ConversationSummarizer.get_chat_context()
    """
    
    def __init__(self, llm_gateway, keep_recent: int = 20,
                 compression_trigger: int = 40,
                 aggressive_trigger: int = 60):
        self.llm = llm_gateway
        self.keep_recent = keep_recent           # 始终保留的最近消息数
        self.compression_trigger = compression_trigger  # 触发压缩的消息数
        self.aggressive_trigger = aggressive_trigger      # 触发激进压缩的消息数
    
    def compress(self, messages: List[dict], token_budget: int = 0) -> tuple:
        """
        智能压缩对话历史
        
        返回: (compressed_messages, summary_str)
        """
        total = len(messages)
        
        if total <= self.keep_recent:
            return messages, ""
        
        # 选择压缩模式
        if total >= self.aggressive_trigger:
            mode = CompressionMode.AGGRESSIVE
        elif total >= self.compression_trigger:
            mode = CompressionMode.SLIDING_WINDOW
        else:
            return messages, ""
        
        # 分离：需要压缩的旧消息 + 保留的最近消息
        old_messages = messages[:-self.keep_recent]
        recent_messages = messages[-self.keep_recent:]
        
        # 执行压缩（带降级）
        summary = self._compress_with_fallback(old_messages, mode)
        
        return recent_messages, summary
    
    def _compress_with_fallback(self, messages: list, mode: CompressionMode) -> str:
        """
        带降级链的压缩
        降级：SLIDING_WINDOW -> AGGRESSIVE -> TEMPLATE
        """
        if mode == CompressionMode.SLIDING_WINDOW:
            summary = self._llm_summarize(messages, max_chars=300)
            if summary:
                return summary
        
        if mode == CompressionMode.AGGRESSIVE:
            summary = self._llm_summarize(messages, max_chars=150)
            if summary:
                return summary
        
        # 最终降级：模板摘要（不调用LLM）
        return self._template_summarize(messages)
    
    def _llm_summarize(self, messages: list, max_chars: int = 300) -> str:
        """LLM摘要"""
        text = "\n".join(
            f"{'用户' if m.get('is_user') else '我'}: {m.get('content', '')}"
            for m in messages[-30:]  # 只摘要最近30条旧消息
        )
        
        prompt = (
            f"请用不超过{max_chars}字总结以下对话要点：\n"
            f"保留：话题、关键信息、重要决定、情感变化。\n\n"
            f"{text[-3000:]}"  # 截断输入
        )
        
        try:
            result = self.llm.chat_sync(query=prompt, max_tokens=max_chars)
            return result.strip()
        except Exception:
            return None
    
    def _template_summarize(self, messages: list) -> str:
        """模板摘要（不调用LLM）"""
        topics = set()
        for m in messages:
            content = m.get("content", "")
            # 简单提取话题关键词（取每条消息的前10个字）
            if len(content) > 5:
                topics.add(content[:10])
        
        return (
            f"[摘要] 共{len(messages)}条对话，"
            f"话题涉及：{'、'.join(list(topics)[:5])}等。"
            f"详细内容已压缩。"
        )
```

### 4.1 情感预测与累积机制

#### 4.1.1 问题分析
当前情感引擎每轮独立分析用户情感，没有：
- 基于历史序列的情感趋势预测
- 多轮情感累积（连续3轮生气应升级）

#### 4.1.2 具体改造方案

**改造文件**：`my_character/emotion_engine.py`

```python
# emotion_engine.py 新增

from collections import deque

@dataclass
class EmotionHistory:
    """情感历史追踪器"""
    recent_emotions: deque = field(default_factory=lambda: deque(maxlen=10))
    consecutive_counts: dict = field(default_factory=dict)  # 连续计数器
    
    def record(self, emotion: 'Emotion'):
        self.recent_emotions.append(emotion)
        # 更新连续计数
        if emotion == self._last_emotion():
            self.consecutive_counts[emotion] = self.consecutive_counts.get(emotion, 0) + 1
        else:
            self.consecutive_counts[emotion] = 1
    
    def _last_emotion(self) -> Optional['Emotion']:
        return self.recent_emotions[-1] if self.recent_emotions else None
    
    def get_consecutive(self, emotion: 'Emotion') -> int:
        return self.consecutive_counts.get(emotion, 0)
    
    def should_escalate(self, emotion: 'Emotion') -> bool:
        """检查是否应该升级情感强度"""
        return self.get_consecutive(emotion) >= 3

class EmotionPredictor:
    """
    情感预测器
    基于历史情感序列预测用户下一轮可能的情感状态
    
    集成位置：EmotionEngine.analyze() 返回后
    """
    
    # 情感转移概率矩阵（基于统计的先验）
    TRANSITION_PRIORS = {
        ("NEUTRAL", "HAPPY"): 0.3,
        ("NEUTRAL", "SAD"): 0.1,
        ("HAPPY", "NEUTRAL"): 0.4,
        ("SAD", "SAD"): 0.3,       # 伤心容易持续
        ("ANGRY", "ANGRY"): 0.4,    # 生气容易持续
        ("ANGRY", "SAD"): 0.2,      # 生气后可能转为伤心
        ("LOVELY", "HAPPY"): 0.5,   # 撒娇后容易开心
    }
    
    def predict_next(self, history: EmotionHistory) -> Optional['Emotion']:
        """基于历史预测下一情感"""
        if len(history.recent_emotions) < 3:
            return None
        
        last = history._last_emotion()
        consecutive = history.get_consecutive(last)
        
        # 连续3轮以上同一情感，预测持续
        if consecutive >= 3:
            return last
        
        # 基于转移先验预测
        candidates = []
        for (prev, next_e), prob in self.TRANSITION_PRIORS.items():
            if prev == last.value if hasattr(last, 'value') else str(prev):
                candidates.append((next_e, prob))
        
        if candidates:
            candidates.sort(key=lambda x: x[1], reverse=True)
            return candidates[0][0]
        
        return None
```

### 4.3 BM25混合搜索

#### 4.3.1 问题分析
当前RAG引擎中BM25已被注释掉（`HAS_BM25 = False`），关键词检索仅为SQLite LIKE查询，没有倒排索引。Letta使用RRF（Reciprocal Rank Fusion）融合全文搜索和向量搜索排名。

#### 4.3.2 借鉴来源：Letta `message_manager.py` 的RRF融合

**核心算法**：
```
RRF_score = 1 / (k + vector_rank) + 1 / (k + fts_rank)
```
其中k=60（标准RRF参数）

#### 4.3.3 具体改造方案

**改造文件**：`rag_engine/rag_engine.py`

```python
# rag_engine.py 改造

# 1. 启用BM25
HAS_BM25 = True  # 从 False 改为 True

# 2. 添加RRF融合排序

def rrf_fusion(vector_results: list, bm25_results: list, k: int = 60) -> list:
    """
    RRF（Reciprocal Rank Fusion）融合排序
    借鉴Letta message_manager.py的混合搜索排序
    
    参数:
        vector_results: [(doc, score), ...] 向量搜索结果
        bm25_results: [(doc, score), ...] BM25搜索结果
        k: RRF参数（默认60）
    
    返回:
        融合排序后的结果列表
    """
    # 构建排名映射
    vector_ranks = {doc: rank for rank, (doc, _) in enumerate(vector_results)}
    bm25_ranks = {doc: rank for rank, (doc, _) in enumerate(bm25_results)}
    
    # 收集所有文档
    all_docs = set(vector_ranks.keys()) | set(bm25_ranks.keys())
    
    # 计算RRF分数
    rrf_scores = {}
    for doc in all_docs:
        v_rank = vector_ranks.get(doc, len(vector_results))
        b_rank = bm25_ranks.get(doc, len(bm25_results))
        rrf_scores[doc] = 1.0 / (k + v_rank + 1) + 1.0 / (k + b_rank + 1)
    
    # 按RRF分数排序
    sorted_docs = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)
    return sorted_docs
```

**集成位置**：`rag_engine.py` 的检索方法中，替换现有的简单加权（向量0.7+关键词0.3）为RRF融合

**依赖**：`pip install rank_bm25`（如果当前未安装）

## 五、P3级升级方案

### 5.1 记忆情感标注检索

#### 5.1.1 问题分析
记忆存储时有 `emotion_tag`，但检索时未利用情感进行过滤/排序。当用户表达特定情感时，优先检索到相同情感色彩的记忆可以提升回复的相关性。

#### 5.1.2 具体改造方案

**改造文件**：`memory/memory_pipeline.py` 的 `retrieve_context()` 方法

```python
# memory_pipeline.py retrieve_context() 改造

async def retrieve_context(self, query: str, emotion_state=None, top_k=5):
    """检索上下文（新增情感过滤）"""
    
    # 现有检索逻辑
    episodic_results = await self.episodic_mem.search(query, top_k=top_k * 2)
    semantic_results = await self.semantic_mem.search(query, top_k=top_k * 2)
    
    # === 新增：情感加权 ===
    if emotion_state and hasattr(emotion_state, 'primary_emotion'):
        current_emotion = emotion_state.primary_emotion.value if hasattr(emotion_state.primary_emotion, 'value') else str(emotion_state.primary_emotion)
        
        def emotion_boost(result):
            """对情感匹配的记忆进行加权"""
            metadata = result.get('metadata', {})
            stored_emotion = metadata.get('emotion_tag', '')
            if stored_emotion == current_emotion:
                return result['score'] * 1.3  # 相同情感+30%权重
            elif self._is_related_emotion(stored_emotion, current_emotion):
                return result['score'] * 1.1  # 相关情感+10%权重
            return result['score']
        
        episodic_results = [
            {**r, 'score': emotion_boost(r)} for r in episodic_results
        ]
        semantic_results = [
            {**r, 'score': emotion_boost(r)} for r in semantic_results
        ]
        
        # 重新排序
        episodic_results.sort(key=lambda x: x['score'], reverse=True)
        semantic_results.sort(key=lambda x: x['score'], reverse=True)
    
    # 截取top_k
    return episodic_results[:top_k], semantic_results[:top_k]

def _is_related_emotion(self, e1: str, e2: str) -> bool:
    """判断两种情感是否相关"""
    related_groups = [
        {"开心", "调皮", "撒娇", "温柔"},
        {"伤心", "疲惫", "平常"},
        {"生气", "吃醋", "傲娇"},
    ]
    for group in related_groups:
        if e1 in group and e2 in group:
            return True
    return False
```
