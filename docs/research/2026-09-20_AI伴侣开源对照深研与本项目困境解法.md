## 2. 按困境逐项：对端怎么做 → 我们怎么改

### P1 回复不跟话题 / 记忆「说过的」

**nana（`memory_extract.md` + 结构化摘要）**
- 每段对话抽：`summary / topics / emotional_valence / importance / user_facts{basic_info,preferences,interests,life_events,relationships}`
- **只提取用户明确说过的新信息**，禁止编造
- `topics` 逗号关键词 → 供后续检索/续聊

**my-raze（`memory.ts` + `shared/memory.ts`）**
- 每 **10 条消息**抽一次（`EXTRACTION_EVERY_N_MESSAGES=10`）
- 类别：`fact / preference / event / relationship`（**relationship 专门记「我们之间」**）
- **近重复不插入，而是 reinforce**（加权 + 刷新 freshness）
- 注入条数 **随亲密度变化**：`k = 4 + ceil(level/2)`，容量 `20+level*10`

**Artemis（`memory_recall.py`）**
- 召回 query = **本轮用户输入 + 最近 2 条用户话**（不是系统拼一堆）
- 相关阈值 **0.3**（轻量 embedding 天然偏低）；top_k=5
- 记忆片段带 `trust`（explicit 优先）与 `token_budget`

**对照本项目困境**
- 我们有 DB 会话上下文（v1.17）+ user_facts 隔离（v1.22），但：
  - fact_extractor **无 topics/relationship 类的「续聊钩子」**
  - 注入数量**不随亲密度/关系阶段缩放**
  - 多次同一事实**未 reinforce**（access_count 刚接上权重，但**写入路径未合并重复**）

**落地方案（建议 P1 批次）**
1. `fact_extractor` 输出扩展：
   - 增加 `topics: list[str]`
   - `commitment` 已有 → 增加 `relationship`（约定/共同经历/称呼变化）
2. `user_facts` 表加 `topics TEXT` + `last_seen_at`；`add_fact` 遇 near-dup（与 my-raze 相同 bigram 或 similarity_threshold 0.85）→ **update confidence + last_seen + access_count**，不插新行
3. `get_memory_context` 注入预算：
   ```
   k = min(4 + ceil(affinity_level/2), 10)   # 对齐 my-raze
   ```
   优先：今日/本周 relationship+commitment > preference > 普通 fact
4. prompt 注入模板增加一行：
   ```
   [可续聊的最近话题] {topics 最多3个}
   [我们之间] {relationship facts 最多2条}
   ```

### P2 主动消息：从「紧迫度启发式」到「关系阶段 × 缺失时长 × 注意力」

**nana Heartbeat（`heartbeat.py`）— 可直接抄门控结构**
```
60s tick 五道门：
  0 初始化完成
  1 活跃时段 8:00–23:00
  2 无 pending（TTL 5min 丢弃）
  3 距上次主动 ≥ 5min
  4 至少有过一次互动
  5 response_rate 概率门控（≥0.15 才可能调 LLM；random() < rate 才真调）
response_rate:
  互动 → 0.4
  每 tick ×0.997
  沉默 >30min → +0.003/tick（封顶 1）
  发送成功 → ×0.3；LLM 决定 wait → ×0.7
一次 LLM 同时：决策 action=send_message|wait + 生成正文
```

**MetaPact HEARTBEAT.md — 阶段语义**
| 阶段 | 未互动阈值 | 内容风格 |
|------|-----------|----------|
| 1 初识 | 48h | 天气/轻微分享，不亲密 |
| 2 | 24h | 日常分享+近况 |
| 3 男女朋友 | 12h | 关心工作 |
| 4 热恋 | 8h | 撒娇思念 + 5% 轻情趣 |
| 5 永恒 | 6h | 深情 + 8% |

`heartbeat-check.sh`：思念值 `base 8–15 + current*5/100 + random 0–4`，**≥80 触发**；情绪值随触发衰减；**01–08 点暂停累积**。

**对照本项目**
- 我们 ASE 有 urgency 六维 + quiet_hours + commit_sent 解耦（v1.13）✓
- 但：
  - **没有 response_rate / 概率门**（容易「每到点必发」或「配额用尽」）
  - **没有按关系阶段调整「该不该亲密/该等多久」**
  - 发送后 urgency.reset 全清，不像 nana「发送后 rate×0.3」

**落地方案（建议 P2 批次）**
1. 在 `ASEEngine` 旁挂 **AttentionGate**（对齐 nana）：
   - 字段：`response_rate`, `last_interaction`, 与现有 `_hours_since_last_chat` 并行
   - `can_generate()`：quiet_hours 之外，再加 `rate >= threshold and random() < rate`
   - 互动时 `rate = 0.4`；tick 衰减；沉默累加；**commit_sent 后 rate*=0.3**
2. **阶段化间隔**（对齐 MetaPact，用本项目 affinity_level 0–8 映射）：
   ```
   level 0-1 → 间隔≥48h 才考虑主动，文案偏礼貌
   level 2-3 → ≥24h
   level 4-5 → ≥12h
   level 6-7 → ≥8h
   level 8   → ≥6h
   ```
   读取 `shisi.affinity.scale.points_to_level(affection_points)`
3. 主动消息 prompt 模板注入：
   ```
   [关系阶段] {stage_hint}   # 从角色卡 mes_example/关系阶段表取
   [距上次聊天] {hours}
   [今天心情上下文] {recent user facts 1-2条，仅本人}
   ```
4. **禁止**：静默时段生成后扣配额（已有）；连续 2 条同类型 → 强制换类型（已有 `_recent_types`）

### P5 情感与亲密度

**nana `emotional_state.py`（可借鉴产品语义）**
- 情绪：valence/arousal/dominant + intensity，词典映射
- 关系：`affection / trust / familiarity / stage / interaction_count / first_met`
- **阶段升级三条件全满足才升**（affection+trust+interactions）
- **阶段带说话风格 hint**（stranger 极度傲娇短回复 → special 撒娇）
- 跨天情绪衰减 50%；离线每小时 0.9 衰减
- 每次互动：`affection += 0.002*(1-a)` 递减增长

**Artemis `EmotionScorer`**
- 词典累计打分 + **最长匹配压制**（「不开心」压住「开心」）
- 阈值 1.0；argmax 决胜 —— **零 LLM、可测**

**我们已做**
- `affinity_scale` 唯一刻度 + `affinity_state` 持久化 ✓

**补强**
1. **阶段 hint 进 prompt**：在 `scale.points_to_level` 旁增加 `STAGE_HINTS[0..8]`，注入 system prompt 一行（对齐 nana）
2. **三条件升级可选**：当前 emotion_engine 主要靠 affection_points；可加 trust 简化版=「用户回复率×互动天数」由 AttentionGate 产出
3. **词典情感打分**作 EmotionEngine rule 分类的**增强/校验**（Artemis 模式），LLM 失败时用词典 best()
4. 离线衰减：`user_scheduler` 启动恢复 affinity 时，按离线小时数对 mood（若有）做 0.9^n 衰减——亲密度本身我们选择**不衰减**（产品可感差），可只衰减「当日情绪」

## 5. 代码级接口草案（批次2 AttentionGate）

```python
class AttentionGate:
    DECAY = 0.997
    ACCUM = 0.003
    SILENCE_S = 1800
    BOOST = 0.4
    THRESHOLD = 0.15

    def on_user_message(self): self.rate = self.BOOST; self.last_it = now()
    def tick(self):
        self.rate *= self.DECAY
        if silence > self.SILENCE_S: self.rate = min(1, self.rate + self.ACCUM)
    def allow(self) -> bool:
        return self.rate >= self.THRESHOLD and random.random() < self.rate
    def on_sent(self): self.rate *= 0.3
    def on_llm_wait(self): self.rate *= 0.7

# ASE.tick 门控顺序建议：
# quiet_hours → stage_min_gap(level) → freq_controller → attention.allow() → generate
```
