## ⚠️ 1. 关键设计约束（决定方案形态）

**`chat(messages=...)` 不能用。**
`llm_provider/llm_gateway.py:305-306`：
```python
def _build_messages(self, query, system_prompt, history, messages):
    if messages:
        return messages      # ← 一旦传 messages，system_prompt 与 history 全部丢弃
```
→ 若用 `messages=` 塞图片，**角色人设（system_prompt）与对话历史会一起丢失**，陪伴体验直接崩。

**因此 B 的实现路径是：不改 messages 组装方式，而是给 `chat()` 增加一个 `attachments` 参数，把图片 content part 追加到最后一条 user message 上。**

## 2. 目标数据流

```
微信图(type:3)
  → wechat_connector 解析 image_data
  → 归一化：裸 base64 → data:image/<fmt>;base64,…（multimodal 内）
  → [B 主路径] process_message(..., attachments=[{type:image_url,…}])
       → optimized_orchestrator:809 把 attachments 透给 chat()
       → llm_gateway._build_messages 追加到末条 user message
       → 视觉模型直接看图 + 保留 system_prompt/history
  → [A 降级] 视觉模型不可用/超时/超大小 → 复用既有 VisionHandler 生成描述文本
       → 作为 user_msg 文本入同一管线（与 ASR 的既有降级模式一致）
```

## 4. 降级规则（A）

触发条件（任一）：`mode=describe` / 未配置 `vision_model` / 图片超 `max_bytes` / 视觉调用超时或异常。
行为：调既有 `VisionHandler.process(image_data)` → 得到描述文本 → 作为 `user_msg` 入管线；失败再降级为既有占位文案 `[收到一张图片]`。
**与 ASR 的既有降级模式完全一致**（`_transcribe_voice:925` 识别 `[语音消息` 前缀返回 `""`），不引入新范式。

## 5. 隐私约束（生物特征红线）

- 图片**只在内存流转**，任何环节**不落盘**（不写 `data/`、不写临时文件）。
- 日志**禁止**打印 base64 或图片字节（现有 `:803-806` 的 `[wx][step=receive]` 只打 `text`，需确认不误打图片）。
- 后续 V3 人脸能力接入时复用本文档的「显式告知 / 同意 / 不落盘」机制（报告 §4）。
