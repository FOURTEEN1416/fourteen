# ADR-0005：前端 API 客户端按业务域拆分

## 状态
Accepted

## 上下文
前端 `api/client.ts` 原为一个"上帝文件"，包含所有后端 API 调用（聊天、训练、克隆、系统、角色……），超过 400 行。每次改一个功能都要在这个文件里搜索/增加，合并冲突高发。

## 决策
将 `client.ts` 按业务域拆分为独立的领域文件 + 一个薄的编排层：
- `api/chat.ts` — 聊天相关
- `api/training.ts` — 训练相关
- `api/clone.ts` — 克隆相关
- `api/system.ts` — 系统/工具/健康相关
- `api/characters.ts` — 角色/音色/角色卡/记忆相关
- `api/client.ts` — 仅保留：HTTP 客户端实例 + 各领域文件的 re-export + 统一类型

每个领域文件从 `client.ts` 导入 `client` 实例，自己管理该域的所有接口。

## 影响
- 正面：改角色功能只用看 `characters.ts`，不会动到聊天代码
- 正面：文件从 1 个 400 行 → 6 个平均 80 行
- 正面：合并冲突概率降低 80%
- 代价：需要额外维护 re-export 列表（每次加接口要在 `client.ts` 里加一行）

## 对应 Fitness Function
FF-0006：`client.ts` 禁止包含 `export async function` 定义（只能有 re-export）
