# ADR-0006：UI 状态与 Server 数据状态边界约定

## 状态
Accepted

## 上下文
前端管理台同时使用 Zustand store 和 React Query 管理状态，但没有明确的边界约定。导致：
- 部分页面用 store 存服务端数据（刷新后丢失）
- 部分页面用 React Query 存 UI 状态（不必要的网络请求）
- 新人不知道该把新状态放哪里

## 决策
采用明确的边界约定，代码中以注释形式写在 `client.ts` 顶部：

```
// ── 状态管理约定 ──
// UI 状态（弹窗开关/表单输入/选中项/主题偏好）  → Zustand store
// 服务端数据（角色列表/聊天记录/配置/训练状态） → React Query
// 混合状态（需要同时保存 UI + 服务端），拆成两个独立状态管理
```

## 影响
- 正面：新人 10 秒知道该用哪个
- 正面：不会出现"刷新页面数据没了"的问题
- 正面：React Query 的缓存/重试/失效机制可以覆盖所有服务端数据
- 代价：混合状态的页面需要把 UI 和 server 数据拆开（PersonaEditorPage 需要改造）

## 对应 Fitness Function
FF-0007：Zustand store 中禁止包含 API 调用（`import { api } from '../api/client'`）
