# ADR-0001：关于采用架构决策记录的决定

## 状态
Accepted

## 上下文
项目架构决策散落在聊天记录和代码注释中，新加入者（包括未来的 AI Agent）无法快速了解"为什么这样做"。缺少决策追溯机制，每次重构都需重新推演。

## 决策
引入 ADR（Architecture Decision Record）体系，所有影响项目结构的决策必须写成 ADR 并存于 `docs/adr/`。

规则：
- 每个 ADR 用 MADR 格式，文件名 `ADR-{编号}-{简短标题}.md`
- 状态流：Proposed → Accepted → Deprecated → Superseded
- 当新决策替代旧决策时，旧 ADR 标记为 Superseded，指向新 ADR
- 每个活跃 ADR 必须有对应的 Fitness Function（架构约束检查）

## 影响
- 正面：决策可追溯，新人 5 分钟理解"为什么"
- 正面：重构时能明确知道哪些约束还在生效
- 代价：每次架构变更多花 20 分钟写 ADR

## 对应 Fitness Function
FF-0001：ADR 目录完整性检查（CI 中检查 `docs/adr/` 不空）
FF-0002：ADR 引用完整性（Superseded 标记必须指向存在的 ADR）
