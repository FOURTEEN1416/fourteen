# ADR-0014：角色成就体系

**状态**：提案（待实现）  
**日期**：2026-09-01  
**关联**：`docs/FUNCTION_INVENTORY.md` 状态中心 GAP-5、`docs/history/2026-05-29-design-vs-current-gap.md`

## 背景

历史设计将状态中心定义为“统计卡片、情绪分布、亲密度趋势、成就”四类信息，但当前代码没有成就数据模型、端点、触发器或 UI。`achievement_ratio` 仅是心理画像字段，不能当作成就系统使用。

## 决策

建立**角色维度**的轻量成就系统。成就属于绑定角色，不属于全局用户；同一用户的不同角色互不串扰。第一阶段只提供可解释的里程碑，不提供排行榜、付费激励或社交比较。

### 第一阶段成就类别

- **陪伴**：完成首次对话、累计对话天数（1/7/30）
- **记忆**：产生首条长期记忆、累计记忆条目（10/50）
- **互动**：完成首次主动消息、首次语音互动
- **探索**：完成首次知识库导入、首次重要日期配置

每个成就包含稳定 `achievement_id`、名称、简短说明、类别、解锁条件、解锁时间和当前进度。条件必须是可从现有事件/持久化数据重算的确定性规则，不依赖 LLM 自由判断。

## 数据与接口草案

建议新增角色隔离表 `character_achievements`：

- `character_id`（外键/逻辑外键）
- `achievement_id`
- `progress`、`target`
- `unlocked_at`（未解锁为空）
- `created_at`、`updated_at`
- 唯一约束：`character_id + achievement_id`

建议接口：

- `GET /api/characters/{character_id}/achievements`：返回成就清单、进度与解锁状态
- `POST /api/characters/{character_id}/achievements/recalculate`：管理员或内部任务重算；普通用户不直接伪造解锁

优先复用现有聊天、记忆、主动消息、语音、知识库和重要日期的事实源；不复制整份消息内容，不在响应中返回敏感聊天原文。

## 触发策略

先采用“事件后重算 + 每日维护兜底”两条路径：

1. 既有成功事件完成后发送内部领域事件；成就服务按角色 ID 增量更新。
2. 每日维护任务对活跃角色执行一次幂等重算，修复历史数据或漏事件。
3. 解锁写入必须幂等；重复事件不得重复通知。
4. 成就通知默认只在状态中心展示，不主动发送微信消息，避免打扰和隐私泄露。

## 隐私与边界

- 成就只展示统计结果，不展示聊天原文、第三方联系人或心理诊断结论。
- 删除角色时级联删除其成就；导出/删除用户数据时必须一并处理。
- 不把成就用于模型提示词，不影响亲密度、内容安全或推荐决策。
- 不设计赌博化连续签到、付费解锁、公开排行或未成年人竞争机制。

## 验收标准

实现前必须先补测试：角色隔离、首次事件、累计阈值、重复事件幂等、删除级联、权限校验、空态和错误态。完成后纳入四项回归门：pytest、Vitest、Playwright E2E、前后端对齐扫描。

## 未决项

成就名称、文案和阈值需在 UI 开发前确认；本 ADR 不代表功能已实现，不得在功能清单中标记为“已完成”。
