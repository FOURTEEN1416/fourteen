## 一、方法：为什么是"双向收敛"而不是"移植"

### 1.1 三条硬约束（决定设计形态）

1. **不引入兜底层 / 不新开真源**（项目宪法 + 基线①§5.1）：小凌架构**只能映射到既有 owner**，落地形态是"替换既有实现"而非"叠加新模块"。
2. **13k prompt 是成本红线**（基线①§3.2 债务 2）：任何来自小凌的模块，**必须证明 token 净减或不增**；纯"再加一层提示词"的做法一律否决（这直接判了"心光=再加提示词"的死刑）。
3. **确定性优先**（基线①§5.1 第 4 条）：漂移/竞争/门槛全部落为纯函数，LLM 只在生成文本处出现。

### 1.2 证据分级（本报告全文沿用）

| 级 | 含义 | 小凌侧来源 | 可信度处理 |
|---|---|---|---|
| **A** | 代码级（有可执行实现截屏） | `forget.py`（`frames/7683930568145161506/u_25~u_27`） | 可直接采信**逻辑**；参数值是**演示拟合** |
| **B** | 表格级（有工程表格截屏） | 参数表 + 「出生前参数设计说明 V0.3」（`frames/7684439164087726043`） | 可采信**结构**；数值未标定 |
| **C** | 手稿级（有手写公式稿） | 十格手稿（`frames/7684709586699591026/image_0.jpg`） | 可采信**变量定义**；权重未定 |
| **D** | 口播级（仅口述） | 转写正文 | 仅作**意图证据**，不作规范 |

> ⚠️ 关键纪律：**手稿（C）不是规范版本**——W-A 已证激活值公式有 3 种表述（手稿 5 项 / 口播 6 项 / 口播 7 项），且手稿公开**更晚却项数更少**。凡涉及数值，一律回落到"需自标定"。

### 2.3 参数域规范（从「出生前参数设计说明 V0.3」提炼为可实现 spec）

```python

    "key":         "...",          # 参数名
    "kind":        "Sensitivity",  # 11 类之一（见下）
    "initial":     0.55,           # 出生初值：只是起点，不等于永久人格

# 与"参数"分层的运行时状态（不是参数，每 tick 变）
```

## 四、可落地的收敛设计（设计级）

### D1 参数域：给"可成长参数"补 `min / max / plasticity`

**落点**：`shisi/affinity/enhancer.py`（现 `_min/_max` 是**全局 0~100**）+ 角色卡数值字典 + 未来成长层。

**设计**：
1. 全局 `[min,max]` **保留**（作兜底边界），在其上为**每个可成长参数**加 `(min_i, max_i, plasticity_i)`。
2. 更新规则（纯函数，确定性）：
   `Δp = plasticity_i × α × (evidence − p)`，再 `p ← clamp(p + Δp, min_i, max_i)`
   - `plasticity = 0` → 参数**冻结**（对齐"0=基本固定"）
   - `max_i` 的作用是**防无限漂移**，不是限制表现
3. **`plasticity` 的三档建议**（对齐原表语义 + 本项目安全偏好）：身份/安全类 `0.0`（冻结）；关系类 `0.1~0.2`；偏好类 `0.4~0.6`。
4. **ΔTrust 的多变量化**：`enhancer.update()` 现在只吃一个 `delta`。设计为**旁路不改签名**——新增 `ΔTrust = αP + βC − γV − δB` 的计算层，把结果**作为一个 delta** 传入既有 `update()`，从而**不动既有调用方与测试**。权重 `α/β/γ/δ` 初值取 `1/1/1.2/1.5`（负面权重大于正面，对齐"信任积累慢、崩塌快"），**标注为待标定**。
   ➕ **数据来源已就位（2026-09-20 复核）**：四个变量里 **`C`（承诺兑现 Consistency）已有现成抽取器**——`shisi/memory/legacy/fact_extractor.py:30,64-67` 新落地 `commitment` 类别（正则：`提醒我`/`叫我`/`说好了`/`说定了`/`约好`/`答应`/`一言为定`/`拉钩`，注释明写"这类事实是『你不是答应提醒我吗』追问的全部答案来源"）。
   ⚠️ **但"已抽取"≠"已兑现"**——`commitment` 只把**用户的请求**存为事实，**没有任何"是否真的做到"的回执字段**。ΔTrust 的 `C` 项需要的是**兑现率**，故 D1 必须补一步：给 `commitment` 事实加**状态回执**（`pending` / `fulfilled` / `missed`），由后续对话或调度器回填。**这一步不做，`βC` 项就是空转。**

### D2 遗忘三分离：从"按重要性选 λ"改为"按变量分离"（**不新增参数，只改选择键**）

**现状**：`ForgettingManager.retrieval_weight` → `λ = λ_high if importance≥0.7 else λ_low`，即**单量、按重要性二档**。

**收敛设计**（最小改动，最大化收益）：

| 改动 | 内容 | 依据 |
|---|---|---|
| ① **变量分离** | 把 S（意义）/ D（细节）/ E（情绪残留）拆成三个独立衰减，各带自己的 λ | 小凌 A 级代码：`lambda_d=0.36 / lambda_e=0.034`（λ_e 仅 λ_d 的 1/10.6） |
| ② **λ 初值直接复用现存比例** | `λ_D = 0.1`（沿用 `lambda_low`）、`λ_E = 0.1/10 ≈ 0.01`（沿用 `lambda_high`）——**即：本项目现成的 0.1 / 0.01 恰好就是"细节 λ / 情绪 λ"的合理初值**，只需把"选键"从 `importance` 换成 `变量` | 跨源收敛：本项目 10× vs 小凌 10.6×（**独立同量级**，是可采信的先验） |
| ③ **回忆强化** | `R` 里加入 `w5·Recall`，并**让 `access_count` 真的自增**（现状：**只读、从不自增、指数模式不用**，见 §五B4） | 小凌 A 级 `w5*Recall`；"越回忆越牢"是常识性产品预期 |
| ④ **保底留痕** | 把 `should_delete` 的"删"改为"降级"：`F` 最低 1 条；事实层改为**标记 `dormant` 不物理删除** | 小凌 A 级 `max(1, floor(...))`；且**硬删除对陪伴类产品是净损失**（用户会发现"它忘了我告诉它的事"） |
| ⑤ 线性 vs 指数统一 | `DecayEngine` 是**线性**（好感度），`ForgettingManager` 是**指数**（事实）——**保留差异但显式记账**：好感度用线性（人为可控，宽限期可解释），事实用指数（对齐艾宾浩斯） | 避免"两套衰减模型"继续成为隐性债务 |

### D3 绝对门槛 + 双档拒答（把已声明未接线的 `similarity_threshold` 接上）

**现状**：`retrieve_context` 只有 `top_k`；`config/shisi.yaml:79 similarity_threshold: 0.85` **零消费点**。

**设计**：三档语义（阈值初值取小凌示例的**结构**，数值待标定）

| 档 | 条件 | 行为 |
|---|---|---|
| 低 | `score < 0.25` | **不注入**（"想不起来"），且**不假装记得** |
| 中 | `0.25 ≤ score` | 注入片段，**带不确定措辞** |
| 高 | `score > 0.65` | 才允许"连贯讲述"（拼接成段） |

- 门槛值**先挂靠既有水位线**（基线①§5.5 反方对策③）：本项目已有 BM25 双路相似度分布，先取**分位数**而非绝对值。
- 纪律：标定脚本**只读零外呼**（基线③W4）。
- **净收益**：门槛是**减法**——不注入即省 token，正好对冲 13k prompt 的成本压力。

### D4 推断内容降级标记（**最低成本、最高收益，建议先行**）

**现状**：`ReflectionEngine` / `ConversationSummarizer` / `cross_session_reasoner` 的产物**无"这是推断不是发生"的标记**，直接进 prompt 与记忆。

**设计**：在产物上挂一个来源标签（三值）：

| 标签 | 含义 | 进 prompt 的措辞 |
|---|---|---|
| `fact` | 用户明说过 / 系统观测到 | 直接陈述 |
| `inferred` | 系统推断（如"他可能在忙"） | **必须带不确定措辞**（"我感觉…"） |
| `reconstructed` | 由片段拼接出的叙事 | **必须在措辞上退回**（"我记不太清了，好像是…"） |

**对齐**：小凌 A 级代码 `系统标记: reconstruction_confidence < 1.0`（事实/重建**分栏输出**）；同时消 WrenWen 坑六（错误认知入记忆）。
**注意**：这不是"多写一段提示词"，而是**已有的产物流水线上加一个字段**——token 增量可忽略。

### D5 时间与节律：三套分类器收敛为单一真源（**P0 前置，见 §五B1**）

**现状**：3 套并行
| 位置 | 时区 | 分段 |
|---|---|---|
| `proactive/ase_engine.py` `_now_local()` | ✅ UTC+8（显式回退） | morning/forenoon/**noon**/afternoon/evening/night（5-9/9-12/12-14/14-18/18-22/else） |
| `my_character/enhanced_prompt_engine.py:35` `TimeContext.now()` | 🔴 **UTC** | morning/forenoon/afternoon/**late_night**（6-9/9-12/12-18/18-22/22-24/else） |
| `my_character/dynamic_anchor.py:65` `time_of_day` | 未核实 | 另一套（`daytime` 等） |

**设计**：
1. **单一真源** = 一个 `get_local_now()`（把 `ase_engine._now_local` 的**正确实现**提为公共 util），所有时间判定改调它。
2. **分段表只留一份**（建议采用 ASE 的 6 段，因其已被主动消息的语义验证过）。
3. **替换清单（4 处，逐处 `file:line`）**：
   - `memory_pipeline.py:210 _is_late_night` + `:250`/`:286`/`:775` 的 UTC 入参 → **最高优先（B1a，已生效）**
   - `memory_pipeline.py:580`/`:683` 的 `date_str = datetime.now(utc)` → 改用本地日期（日记/维护切日）
   - `enhanced_prompt_engine.py:35 TimeContext.now()` → `astimezone`（B1b，潜伏）
   - `dynamic_anchor.py:65 time_of_day` → 需先核实（未验证）
4. `TimeContext` 的 UTC 缺陷一并修掉；`config/shisi.yaml` 的 `app.timezone` **要么接上要么删**（禁止"声明了不读"）。
5. 修正后**主观时间**才有地基（小凌 M12 的 V1.1"系统时间≠主观时间"才有落点）——但主观时间是**新增机制**，不属本批。

### D6 心光：从"提示词模板"升级为"数值门控"（P3，**唯一必须证明 token 净减的一项**）

**现状**：`_build_cognitive_focus_layer` 是**固定 5 问文本块**（每次无条件注入）。它不是心光，是**心光的占位符**。

**设计三步**（每步独立可回滚）：

| 步 | 内容 | token 影响 |
|---|---|---|
| 6a | **容量与竞争**：识海候选（working + episodic + semantic + reflections）统一打 `A` 分（§2.2 收敛公式），按 `A` 排序 + 硬容量（建议 5，**对齐小凌 B 级参数表实测值 `当前意识容量=5.00`**） | **净减**（现在注入 20+ 条，改后 ≤5 条） |
| 6b | **绝对门槛**：`A < threshold` 直接不注入（初始阈值取参数表的 `0.58`，**作先验待标定**） | **净减** |
| 6c | **方向预算**（外界/内部/身体）：给三类候选分配固定配额，避免"回忆淹没当下" | 中性（只是重分配） |
| 6d | 最后才考虑把 `_build_cognitive_focus_layer` 的**文本模板缩为一句**（因为它现在是"教模型做人"的通用指令，价值可由 6a-6c 的实际内容取代） | **净减** |

> ⚠️ **红线**：**不得**把 `_build_cognitive_focus_layer` 之外再加任何新的提示词层。若某步无法证明净减，该步不落地。
> ⚠️ **对齐**：`当前意识容量=5` 与 `阈值 0.58` 来自**参数表实屏（B 级）**，且与口播交叉验证一致——是本项目**唯一有外部依据**的门槛初值（仍需自标定）。

### D7 内驱：六维已有，缺的是"自失效"与"轴间制衡"

**现状**（`ase_engine.py`）：
- `missing_bonus = min(5.0, hours_since_last_chat × 0.5)` —— **关于沉默时长单调递增，永不自我失效**
- `emotion_bonus = 1.5 if emotion in ["伤心","生气"]` —— **把用户情绪低落直接折算为"更该打扰"**
- `urgency_threshold`：config `2.0` / 构造函数默认 `4.0` / 硬编码 `2.0`（`:818`）—— **三处不一致**

**设计**（正面回答 WrenWen 坑二 / 坑七）：

| 改动 | 内容 |
|---|---|
| 7a **missing_bonus 自失效**（坑二） | 沉默 **≠** 需要。加**信息增益闸门**：沉默越久，**发起的信息增益阈值越高**（越长越要"值得才开口"）。落地形态：`missing_bonus` 乘一个随沉默天数**递减**的增益系数（而非线性封顶）。**"用户沉默 = 用户需要"必须从系统假设中删除** |
| 7b **情绪轴解耦**（坑二） | 用户"伤心/生气"**不再直接抬升打扰意愿**（撤掉 `emotion_bonus` 的这条规则或改为**降低**）。对齐红线："**系统不判断用户情绪**"（基线①§5.6） |
| 7c **锚定倒计时**（坑七） | 固定 30 分钟 `min_interval` 属"机器指标全绿、体感非常人机"。改为**锚定最后一条用户消息**的随机倒计时（用户活跃时物理上不触发） |
| 7d **轴间制衡**（jiwen 教训） | "想开口但骄傲高 → 找事做"：新增**轴间抑制规则**（如 `connection` 高 × `pride` 高 → 不投递，转内部独白）。**纯函数**，可单测 |
| 7e **阈值单一真源** | 三处 `2.0/4.0/2.0` 收敛为**一处配置** |

### D8 语义解释层补齐（P1，"已有过滤"→"分类 + 权重"）

**现状**：`should_store_as_fact()` 已能**过滤敷衍消息**（`memory_pipeline:769/789`）。缺的是**分类与入账权重**。

**设计**：复用 `persona_extractor/` 的既有分析器，把入账分为四类并给权重：
`关于自己` / `关于角色` / `关于关系` / `普通信息`——其中"关于自己"权重最高、"普通信息"权重最低。
**目的**：防止"一句话就改人格"（小凌 V1.3 的原始动因）。**不新增 LLM 调用**（复用既有分析器），故 token/成本中性。
