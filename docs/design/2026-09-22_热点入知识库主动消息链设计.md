# 热点入知识库主动消息链设计（W3 窗口，2026-09-22）

> Owner 窗口：`wt/hot-knowledge`（W3 实现窗）。
> 用户裁决的链路方向：**先进知识库、然后整理、再接入主动消息链路——不是主动消息现场调搜索**。
> scheduler / `_init_mixin` 接线归主控，契约见 `docs/board/W3_HANDOFF_WIRING.md`。

## 0. 问题与根因背景

主动消息的「分享」候选（`proactive/ase_engine._try_knowledge_share`）现有内容源只有
角色知识索引（建卡时静态生成，`data/knowledge/{cid}.json`）——角色能聊的"见闻"永远停在
建卡那一刻。要让她"知道最近发生了什么"，热点资讯必须**先采集入库、再整理、经既有供出口
喂给生成**，而不是发消息的瞬间现场调搜索（SearchTool Bing 主链 + DDGS 6s 硬超时 + 熔断，
放在生成路径上会让主动消息挂等网络、且同一条热点每次发送都重复烧配额）。

## 1. 总体链路

```
config/hot_topics.yaml（公共热点查询表）
        │ collect_if_due()（自限速）/ collect_once()（强制一轮）
        ▼
SearchTool（复用，零改动；Bing 主 + DDG 副 + 熔断内置）
        ▼ 归一化去重（标题去空白小写，空则回退 href）
data/hot_topics.json（全局热点池，utils/json_state 唯一 owner，flock 跨 worker）
        ▼ get_hot_context(character_id)（读侧 TTL 过滤 + 人设相关度排序 + 条数上限）
proactive/ase_engine._try_knowledge_share（既有唯一供出口，热点前置拼入 excerpt）
        ▼ LLM 按角色口吻转述 → share 消息（type/generated_by 不变）
```

模块：`shisi/knowledge/hot_topics.py`（采集/整理/存储/过期的唯一 owner）。
入口脚本：`scripts/run_hot_topics_collect.py`（手动跑一轮采集，调试/运维用）。

## 2. 触发方式（裁决：周期函数 + 挂线契约，本窗不造第二条调度）

- **不做**独立线程/cron：生产 4 个 uvicorn worker，各自起线程 = 同一小时重复采集 4 次，
  且绕过 scheduler 的任务治理与可观测（同 `vault_collect` 已有的注册形态）。
- **做**成同步幂等自限速函数 `collect_if_due()`：内部读池 `last_collect_at`，间隔
  （`interval_minutes`，默认 60）未到即返回 `{"skipped": "interval"}`——**任意轮询频率下
  重复调用安全**，scheduler 侧无论每分钟还是每小时注册都不需要再判间隔。永不抛出。
- 挂线契约（`_run_hot_topics_collect` + IntervalTrigger 注册）写入
  `docs/board/W3_HANDOFF_WIRING.md`，交主控收仓时落 `proactive/scheduler.py`（本窗禁改）。
- 过渡期/手动触发：`python scripts/run_hot_topics_collect.py [--force]`。

## 3. 去重 / TTL / 池界

- **去重键** = 归一化标题（`\s+` 去除 + 小写）；标题为空回退 href 小写。同轮内多查询命中
  同题、跨轮重复采集均只计 `duplicates` 不重复入池。
- **TTL**：条目写入时落 `fetched_at` / `expires_at` 两个 **epoch 绝对时刻**——本项目有多起
  naive/aware 相减与 UTC/本地墙钟口径事故（v1.36①、v1.37 块A、v1.25），池内时间判定一律
  epoch 比较，不碰 datetime 混算。默认 48h。
- **两侧生效**：读侧 `read_pool(now=)` 过滤过期项（供出永远拿不到过期热点）；写侧每轮采集
  锁内剪枝（`json_state.update_json` 的 mutate 回调，flock 下读-改-写原子）。
- **池上限** `max_pool`（默认 50）：按 fetched_at 降序截断，溢出丢最旧。

## 4. 整理形态：全局池 + 读侧人设轻过滤（不逐角色采集）

- 采集查询全部是**公共热点关键词**（热搜/新闻/影视/体育/科技），一次采集全员共享——
  41 卡 × 逐角色现场采集是 LLM 与搜索配额双红线。
- 「按角色整理」发生在**读取时**：`get_hot_context(character_id)` 用条目标题/正文 token 与
  角色人设卡文本（name/description/personality，复用 `retriever.KeywordRetriever._tokenize`）
  的重叠数做相关度排序，次键新鲜度；取不到卡（如 "dynamic"、测试环境卡目录为空）退化为
  纯新近序，不报错。注入条数 `max_items_inject`（默认 2）。
- **不写角色 BM25 索引文件**（`data/knowledge/{cid}.json` 结构与 41 卡索引零变更）——静态
  索引没有"过期"概念，热点块进盘即成永久残留（旧热点当近期见闻是内容事故）；TTL 靠池的
  读侧/写侧自然过期。

## 5. 供出收口：既有 `_knowledge_share_func` 通道，不另造第二通道

- 供出口现状（`orchestrator/_init_mixin._inject_ase_knowledge`，本窗只读）：每个 ASEEngine
  实例被注入 `_knowledge_share_func`（→ `CharacterKnowledgeService.get_knowledge_context`）
  与 `_knowledge_character_id`，`_try_knowledge_share` 取 excerpt 喂 LLM。
- **方案对比**：
  - A（选定）：`_try_knowledge_share` 内把 `get_hot_context(cid)` 的格式化热点段**前置拼入
    excerpt**，带「热点（近日公开资讯）」标注。改动仅 `proactive/ase_engine.py` 一处（本窗
    可写 owner 面），`_init_mixin` 注入链零改动。
  - B（否决）：热点作为新 source 进 `CharacterKnowledgeService.search` 可达路径。CKS 检索
    同时服务**对话 RAG**（每轮知识槽），热点混入会污染对话域知识注入、且静态索引文件无
    过期通道，行为半径远大于本任务边界（主动消息供出）。
  - C（否决）：`_knowledge_share_func` 本身改为热点感知——该函数定义在 `_init_mixin`
    （本窗禁改），只能走挂线契约，链路多一跳主控协调成本，且失去人设相关度排序的位置。
- **前置位次**理由：热点有时效性，被 300 字 excerpt 窗挤出即等于没供出；300 字窗内热点
  占先、既有知识随后。`share` 消息类型、冷却/配额账本、`generated_by: "knowledge"` 全不变。
- 既有行为兼容：原实现"`func` 缺失即返回 None"放宽为"func 缺失但池有热点也可供出"；两者
  皆空/皆短 → 仍返回 None 走原模板兜底。

## 6. 失败降级（全链无半成品、不炸主链）

- 单查询搜索炸：吞异常记 warning，该查询计入 `failed_queries`，其余查询照常入池。
- 全部查询挂：**零候选**，池保持旧未过期条目，返回 `{ok: False}`——不发半成品、不清池。
- 落盘炸：warning + `ok: False`，读侧下次照常（json_state 原子写保证无半写文件）。
- 供出侧炸（池读取/人设取卡任意异常）：`get_hot_context` 返回 `""` → `_try_knowledge_share`
  回退既有知识 excerpt → 再空则 None 走模板。**主动消息链路的可用性优先于热点存在性。**

## 7. 配置真源与 fail-safe

`config/hot_topics.yaml`（顶层平铺，逐键与 `load_config()` 一一对应，无死键）：
`enabled / queries / interval_minutes(5..1440) / ttl_hours(1..168) / max_pool(5..200) /
max_results_per_query(1..10) / max_items_inject(1..5)`。
- **缺文件 = 全默认（enabled=true，内置 5 组公共查询）**；坏 yaml / 非 dict / 畸形值 →
  逐键回默认或钳界（NaN/inf/负值/字符串数字全钳除），仿 v1.37⑩ 节流账本容错口径。
- `enabled: false` 双闸：`collect_if_due` 直接 skip（一次搜索都不发）；`get_hot_context`
  返回空串（关闭后存量池条目也不再供出）。

## 8. 隐私与隔离边界

- 热点池**只含公共资讯**：查询表是静态配置的公开关键词，采集入参零用户数据；池文件全局
  单份，不含 user_key/session 维度 → 与多用户隔离约束兼容（不存在"A 的对话进 B 的池"）。
- 反向亦安全：供出只把热点文本喂进 share 生成 prompt，不回写任何用户域数据。
- 池落 `data/hot_topics.json`（gitignored data/），路径经 `utils/project_paths.project_path`
  锚定项目根（防 CWD 相对路径静默丢配置，v1.8 纪律）。
- **测试隔离双保险**：模块路径 `_STATE_PATH`/`_CONFIG_PATH` 为模块级可 monkeypatch；
  新测试 autouse 夹具重定向 tmp_path；同时 `tests/conftest.py::isolate_runtime_state_files`
  增列该池（独立 try 块，防连带跳过——v1.37 自伤事故与 v1.38 conftest 纪律）。
